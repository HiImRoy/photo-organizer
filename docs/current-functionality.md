# PhotoOrganizer 当前功能与界面说明

> 文档状态：基于当前 `main` 分支代码整理。
> 适用版本：`package.json` 中的 `0.1.0`。
> 运行形态：Tauri 2 桌面应用；Vite 浏览器预览仅用于界面验收。

## 1. 产品定位

PhotoOrganizer 是 Windows 优先、本地优先的照片管理工作台。它把“图片的虚拟分类结果”和“磁盘上的真实目录结构”分开保存：用户可以扫描、分析、筛选、预览图片，并生成整理目录与文件名的只读计划，但正常浏览和分析不会修改原始照片。

当前代码的核心原则如下：

- 只扫描用户明确选择的根目录，递归识别 JPEG、JPG、PNG 和 WebP，扩展名不区分大小写。
- SQLite 保存图库、资产、扫描任务、缩略图索引、传统特征、语义结果和整理预览计划。
- 缩略图、屏幕预览、模型和日志保存在应用数据目录，不写回源图库。
- 单张图片分析失败不会终止整次扫描或语义任务。
- 扫描和语义分析在后台运行，并通过进度事件更新界面。
- 当前没有移动、重命名、覆盖或删除源文件的执行入口；图像编辑只允许在预览计划确认后创建一个全新的派生副本。
- “整理预览”是 dry-run：只生成源路径到规划目标路径的映射；导出 JSON/CSV 是唯一由用户明确触发的文件写入。

## 2. 当前实现范围与运行模式

### 2.1 Tauri 桌面模式

桌面模式由 Tauri 承载 React/TypeScript 界面，Rust 负责：

- 目录遍历、文件 fingerprint 和增量扫描；
- EXIF/基本元数据读取；
- 缩略图和屏幕预览生成；
- 亮度、对比度、饱和度、色度、主色和中性色比例分析；
- SQLite 初始化、迁移、筛选、排序、分组和任务持久化；
- 随包 Places365 场景模型、SigLIP 2 Base 摄影题材模型，以及 PicoDet-S + YuNet 主体模型；全部通过 ONNX Runtime 在本机 CPU 上执行；成功装载后会记录 active 模型，下一次启动在后台自动恢复，无需再次点击“装载模型”；
- 语义分析使用单 worker 和默认 4 张图片的小批次（可在设置中调整为 1–8），优先控制 CPU 峰值和内存占用，再按缩略图逐批写入结果；
- 整理规则校验、目标路径规划、冲突诊断和清单导出。
- 收藏、虚拟集合、精确重复分组、本地文本/以图搜索、相似聚类和非破坏性编辑副本。

前端通过类型化 Tauri command/response 和 `scan-progress`、`semantic-progress` 事件与 Rust 通信。应用不开放远程后端或网络服务。

### 2.2 Vite 浏览器预览模式

开发服务器可以使用确定性的视觉夹具，不读取 SQLite、不打开系统目录选择器、不访问个人照片：

```text
http://localhost:1420/?visual-fixture=library
http://localhost:1420/?visual-fixture=scanning
http://localhost:1420/?visual-fixture=error
```

浏览器预览可以体验图库、筛选、排序、选择、详情、单图预览和扫描/语义任务的视觉状态。需要桌面能力的操作会被禁用、返回空结果或显示“仅在桌面应用中可用”，例如真实导入、真实扫描、真实模型准备、重新分析和 Explorer 操作。

## 3. 功能总览

### 3.1 建立与维护图库

1. 首次启动显示“从一个文件夹开始”空状态，入口明确说明本地处理、只读索引和不修改原图。
2. 点击导入后，通过系统目录选择器选择根目录。
3. 导入确认对话框分别提供“导入子文件夹中的图片”和“按子文件夹建立图库结构”。前者关闭时只扫描所选文件夹根目录的图片，后者自动停用；前者开启、后者关闭时递归扫描图片但只建立一个图库。
4. 开启两个选项时，根目录始终建立一个 Library，每个直接包含 JPEG/JPG、PNG 或 WebP 的子文件夹建立独立 Library，空文件夹不建立节点；首次层级按 SourcePath 的物理嵌套关系初始化，后续手动拖放的 `parentLibraryId` 会持久保留。
5. “是否导入子文件夹图片”会持久化到物理图库，重新扫描沿用同一范围；历史图库默认为开启，不改变已有行为。
6. Rust 后台按 ownership scope 扫描；父 SourceRoot 会剪枝已导入的物理嵌套 SourceRoot，子图库由自己的 scope 扫描。通过图库菜单重新扫描父图库时，会把已登记的嵌套子图库一并加入本次扫描。
7. 扫描阶段记录发现、处理、成功、失败、跳过和缺失数量。
8. 扫描完成后将本轮未发现的既有资产标记为缺失；扫描取消不会把尚未遍历的文件误标为缺失。
9. 重复扫描按库内绝对路径和 fingerprint 增量更新；源文件大小或修改时间变化会使相关缓存/分析结果失效。
10. 图库菜单支持重新扫描、在资源管理器中显示、查看图库信息、移出当前父图库和从 PhotoOrganizer 索引中移除。
11. 移除包含子图库的父图库时，会额外询问是否同时移除全部嵌套子图库；选择否只移除当前父图库并保留子图库。两种情况都只清理应用索引、分析结果、任务和应用缓存，不删除或修改源文件。

### 3.2 元数据、缩略图和传统图像分析

扫描后资产可保存并展示：

- 文件格式、大小、修改时间、相对路径；
- 宽度、高度和方向；
- 拍摄时间；
- 相机品牌/型号、镜头、曝光时间、光圈、ISO、焦距等常见 EXIF 字段；
- 应用私有缩略图；
- 亮度、对比度、饱和度、色度；
- 影调等级：低调、均衡、高调；
- 兼容主色十六进制值和类别、多个强调色候选、彩色主色覆盖率、中性色比例；
- 饱和度等级和分析完成/失败状态。

导入时每张图片只生成一份不超过 `640×640` 的应用私有缩略图；亮度、对比度、饱和度和主色等基础特征从同一份缩略图像素缓冲区采样计算，并复用采样网格中的 OKLab 值。Windows 首次导入优先读取有效的 JPEG EXIF 内嵌预览，否则通过 WIC 直接向系统编解码器请求不超过 `640×640` 的 RGBA 输出；应用不会把完整源图像素解码到 `DynamicImage` 或模型输入。WIC 不支持的 WebP 只有在源尺寸本身不超过目标缩略图尺寸时才允许使用有界小图后端，较大的文件明确失败，不回退到完整源图 decode。缩略图缓存和基础分析使用显式版本，旧版本缓存会在重新扫描时失效重建。不超过 32MB 的源图在导入阶段可一次读入，但只用于完整内容 fingerprint、EXIF/内嵌预览元数据和 WIC 的内存流；更大的源图仍采用受内存约束的流式 fingerprint，并通过文件路径进入有界缩略图提取。目录发现阶段只收集路径并先显示完整发现数量，不预读图片字节；随后按 16 张一批处理，批内最多使用 2 个 worker，并以单个 worker 连续处理多张图片来减少线程创建。处理结果以 16 张为一批写入 SQLite；应用侧返回的缩略图像素缓冲严格受目标尺寸约束。超出限制、系统编解码器不支持或损坏的单张图片会记录失败并继续处理其它图片。

缩略图用于网格和胶片栏；网格首批只查询 120 张，滚动接近底部时再追加下一批，缩略图请求只为视口及其附近的卡片排队且最多并发 6 个，不会因图库总数而一次性读取全部缩略图。单图 screen 预览打开时通过有界解码生成并缓存屏幕尺寸 JPEG，避免为查看器建立完整原图像素缓冲。显式 original tier 仍可由当前查看器临时读取原文件，这是查看例外，不得用于导入、分析或模型推理。请求使用 generation token，切换图片时会忽略旧请求，不会把预览资源写回原图库。

### 3.3 浏览、筛选、排序和分组

图库支持：

- 文件名或路径搜索；
- 原始目录前缀筛选；
- 语义标签筛选；
- 语义标签“任一标签”或“同时包含”匹配；
- 尚未语义分析、分析失败快捷筛选；
- 影调筛选；
- 色相范围筛选：通过环形色相控件拖动选择范围和宽度；
- 颜色匹配严格程度：通过横向滑块设置选中色相在有彩色区域中的最低占比，严格程度越高越接近主色调筛选；
- 人工星级筛选（选择一个星级阈值，匹配该星级及以上）；
- 人工色标筛选（红、黄、绿、蓝、紫）；
- 亮度范围和饱和度范围筛选，范围为 0 到 1；
- 拍摄日期起止筛选；
- 按文件名、拍摄时间、修改时间、亮度、饱和度排序；
- 升序/降序切换；
- 通过中央“分组”下拉框按拍摄题材、主体标签、影调、饱和度级别、主色或评分分组；
- 多图预览支持离散网格密度缩放：结果栏滑块按 2、4、6、8、10、12 张/行调整列数，`Ctrl + 滚轮`每次改变两列，不改变缩略图处理方式；
- 左侧筛选栏顶部集中放置颜色范围、颜色匹配严格程度、亮度范围和饱和度范围，底部放置当前图库、收藏和虚拟集合来源；来源只改变统一查询条件，不替换主网格和右侧信息栏；
- 顶部“筛选”弹层只显示当前已应用条件和清除/移除操作，避免同一查询维度在工具栏和侧栏重复出现；
- 选择栏支持加入集合、比较、查找相似、重复审阅和编辑副本；这些工具在主图库下方的上下文区域打开，点击结果会更新右侧焦点资产；
- 连续滚动浏览：首批查询 120 张，接近结果底部时自动追加下一批；界面不显示上一页/下一页分页控件，实际分批查询由 SQLite 层完成。

组合筛选会在顶部显示已应用筛选数量，并提供“清除筛选”。文件夹、标签和数值筛选可以叠加。

### 3.3.1 应用设置

右上角“设置”（快捷键 `Ctrl+,`）提供当前应用级配置，并保存到本地 WebView 存储：

- 设置页采用左侧栏目导航、右侧单页内容的工作区布局，界面、性能和快捷键分开浏览；
- 界面主题：深色/白天；
- 导入并行数：1–2 个缩略图处理 worker，默认 2；
- 分析批大小：1–8 张缩略图，默认 4；分析任务仍保持单任务 worker，避免 CPU 争用；
- 视图、星级、色标和星级增减快捷键：可输入单字符并立即保存；默认 `G` 多图预览、`F` 单图预览。

导入并行数和分析批大小只影响新启动的任务；所有任务仍遵守缩略图专用处理边界。

### 3.4 场景分类与主体标签

环境与可观察场景证据使用随应用分发的 Places365 场景模型；摄影题材候选使用通过资源契约和 SHA-256 校验的 SigLIP 2 Base。环境证据保留在分析结果中，但不再提供“室内/室外”左侧筛选。主体标签使用独立的 PicoDet-S COCO 检测器和 YuNet 人像辅助检测器；任务层可用主体证据补充人像、动物、车辆、食品和植物题材，但不会把主体标签写入主类别组。所有模型都只处理应用生成的 640×640 缩略图或其派生输入，在本机 ONNX Runtime CPU 后端执行，不读取原图参与模型推理。结果保存：

- 标签 ID 和中文显示名；场景结果写入 semantic_labels，主体结果写入 subject_labels；
- 原始相似度和阈值；
- 模型名称、模型版本、分析版本；
- 分析时间、来源 fingerprint；
- 一级分类/辅助标签标记；主体标签没有一级分类属性。

当前对用户开放的摄影题材为：人像、风光自然、街拍纪实、建筑、静物产品、美食、动物、植物、运动、交通工具、文档截图、抽象艺术；没有达到阈值或候选间隔不足的结果归入“抽象艺术”，不再单独显示“未知”。它们用于一级分组，单张图片只选择一个可靠主类别。旅行、商业项目等拍摄意图不从单张图片强行推断。Places365 结果作为环境/场景证据，不直接覆盖题材。主体标签为：单人、多人、动物、车辆、食品、植物；主体标签允许与题材并存，其中单人和多人互斥。历史记录中的旧细分标签会在读取时归并到当前标签，但不再作为新的选择项或自动结果。

摄影题材用于主分组和筛选；环境证据和主体标签与手动标签一起作为辅助筛选。主体标签本身不写入主类别，但经过明确映射的主体证据可以帮助题材层识别人像、动物、车辆、食品和植物，不会因此改写独立的“室内/室外”等环境证据。

环境模型、题材候选模型和主体模型分别显示未就绪/不可用/部分可用/就绪状态；任务本身仍使用排队、运行、暂停、取消中、完成和失败状态。题材候选模型不可用时不会伪造主类别；主体模型不可用时，题材与环境分析仍可运行且不伪造主体标签；YuNet 不可用时，PicoDet 仍可提供单人/多人、动物、车辆等通用主体标签，但不会影响题材“人像”的独立判断。

### 3.5 图片选择与预览

网格中的图片支持：

- 单击激活图片并在右侧显示详情；
- 点击卡片左上角选择/取消选择；
- Ctrl/Command 点击进行多选或反选；
- Shift 点击选择连续范围；
- 双击进入单图预览；
- 选中图片后按 Enter 进入单图预览；
- 按 `G` 切换到多图预览，按 `F` 切换到单图预览；
- 多图模式下按住 `Ctrl` 滚动鼠标滚轮可调整网格缩放，也可拖动结果栏中的“缩放”滑块；
- 网格空白区域点击清除批量选择；
- Esc 清除选择，或在单图模式返回网格。

单图模式提供胶片栏、按当前筛选和排序结果导航、右侧信息面板中的 Lightroom 风格 Navigator、高清预览、Fit/25/50/100/200/400/800/1100% 缩放、滚轮连续缩放、主画布中心基准缩放和放大后的拖动画布。缩放阶梯还支持 6.25% 和 12.5%，不以 25% 或 400% 作为边界；最高 1100% 对齐 Lightroom Classic 的 11:1 级别。

### 3.6 整理预览 Dry-run

“整理预览”用于在真实文件操作前审查目标目录和命名计划。用户可以：

- 选择当前筛选结果、全部图片或用户选中图片作为范围；
- 输入或选择目标根目录；
- 添加、删除、拖动和上下移动目录维度；
- 为每一层目录设置缺失值回退策略；
- 编辑命名模板；
- 设置缺失元数据策略；
- 设置重名策略：添加序号、添加 short hash、跳过；
- 设置序号起点和序号宽度；
- 生成目标目录树和逐文件映射；
- 查看文件数、冲突数、错误数、警告数和预计字节数；
- 点击单条映射查看源路径、规划目标路径、模板变量和问题；
- 导出 JSON 或 CSV dry-run 清单。

规划器会检查源缺失、源文件变化、缺失元数据、非法路径段、Windows 保留名、路径过长、目标越界、重复目标和已存在目标等问题。目标根目录不会被创建，不能位于源图库内部；当前版本没有执行复制按钮。

### 3.7 主界面上下文工具与非破坏性编辑

主界面不再把这些能力包装成替换图库的“智能工作台”。它们按上下文分布在顶部来源、卡片/选择栏和主图库下方的工具区：

- **收藏**：独立于 0–5 星评分的布尔标记；收藏与星级互不覆盖。
- **集合**：多对多虚拟分组，可把当前多选图片加入或移出集合；删除集合不删除图片。
- **AI 搜索**：当前已装载的 SigLIP 2 Base 在本机编码任意文本，使用 768 维图片向量；常见中文主题词先在本地映射为模型提示词。
- **重复清理**：按完整内容 BLAKE3 分组，优先建议保留收藏或高星图片；“清理”只生成“重复待处理”审阅集合，不删除、移动或改名原图。
- **相似聚类**：单图相似搜索使用精确余弦；图库聚类按向量主维度召回候选、精确复核并用 complete-link 约束拆分桥接组。
- **比较**：复用当前多选，支持 2–4 张屏幕预览并排比较和共享的适应/填充模式。
- **图像编辑**：支持 90° 旋转、水平/垂直翻转、中心方形裁剪、曝光、对比度和饱和度；预览和最终导出使用同一 Rust 配方实现。

编辑导出必须先选择目标并生成计划。计划拒绝图库根目录内的目标、已存在目标和不支持的扩展名；执行前重新计算源文件 BLAKE3，先写文件操作日志，再用 `create_new` 创建 JPEG/PNG/WebP 副本。新副本支持“预览撤销”：只有目标仍存在且 BLAKE3 与操作日志一致时才允许删除，哈希已变化则拒绝回滚。任何情况下都不会写回或覆盖原图。

## 4. 主界面布局

主界面由顶部工具栏、最左工作区导航轨、左侧图库/筛选区、中央工作区和右侧信息区组成；导航轨保持窄而无分割线，左右面板靠近中央画布的外缘提供低干扰的可拖拽宽度拉手：

```text
顶部工具栏
┌──────────────────────────────────────────────────────────────┐
```

左侧上方是独立的“图库”区域，下方是独立滚动的“筛选”区域，默认各占左侧可用高度的一半；拖动两区之间的水平分隔线即可调整高度比例，键盘上下方向键每次调整 16px。图库树和筛选内容区都填满各自轨道并独立滚动，影调与颜色位于筛选栏顶部，来源位于筛选栏底部。左右面板始终保留，直接拖动靠近中央画布外缘的短竖向拉手即可调整宽度；拉手默认低对比度，悬停或键盘聚焦时强调，避免额外的卡片和装饰性浮层。

颜色范围查询使用基础分析阶段从应用私有缩略图生成的 12 桶色相直方图，而不是再次读取原图。查询统计选中范围覆盖的色相样本占全部有彩色样本的比例；“颜色匹配严格程度”只改变这个查询阈值，不触发重新分析。这样小面积的红橙色点缀会在较高严格度下被排除，真正以该色相为主的照片才会保留。

点击网格空白区域会清除批量选择。点击文件名较长的卡片时，完整名称可通过 `title` 查看。

扫描启动后显示后台任务面板，阶段包括“准备图库”“发现图片”“生成索引与缩略图”“扫描完成”“扫描已取消”和“扫描失败”。

| -------- | -------------------- | --------------------------------------------------- |

### 5.5 语义任务条

题材、环境与主体使用同一个可恢复语义任务，运行或暂停时显示在中央区域上方，显示处理进度、实际执行后端、失败数以及各模型信息。

| 控件 | 条件                     | 行为                                   |
| ---- | ------------------------ | -------------------------------------- |
| 暂停 | 语义分析运行中           | 协作式暂停当前任务。                   |
| 继续 | 语义分析已暂停           | 恢复当前任务。                         |
| 取消 | 语义任务运行/暂停/取消中 | 请求取消任务；剩余资产不会生成伪标签。 |

语义任务使用单 worker，按同一份缩略图先后执行题材候选、环境与主体推理；单项失败后继续后续资产，某个模型失败不会伪造另一个模型的结果。应用重启时已完成结果保留，运行中的项目可恢复排队；暂停、取消、重跑和按当前模型/分析/分类法版本增量跳过都作用于各层结果。

### 5.6 右侧“图片详情”面板

| 控件           | 条件                                   | 行为                                                                         |

- EXIF：相机、镜头、曝光、光圈、ISO、焦距；
- 影调与色彩：亮度、对比度、饱和度、色度、有彩色占比、中性色占比、影调、兼容主色以及按“强调色/面积色”分组的多候选调色板；候选显示中文类别、面积占比、显著性占比和算法版本；

- 语义标签：摄影题材一级分类、环境证据、主体辅助标签、相似度进度条、对应模型、题材候选模型、版本、后端；主体标签明确显示为非主类别。

### 5.8 整理预览工作区

| 全部图片         | 将图库中全部存在的图片作为整理范围。                                                                                                          |
| 用户选中         | 仅将批量选中的图片作为整理范围；没有选中图片时生成会报错。                                                                                    |
| 目标根目录输入框 | 手动输入目标目录路径。                                                                                                                        |
| 选择             | 打开目录选择器；目标目录不会被创建。                                                                                                          |
| 第 N 层目录维度  | 选择这一层“按什么分目录”：拍摄年份、拍摄月份、拍摄日期、原始目录、拍摄题材、影调、主色或饱和度。第 1 层在最外面，后续层级向内嵌套。           |
| 第 N 层缺失时    | 选择这一层的信息为空时怎么办：日期维度可用文件修改时间，也可以放入“未知”、跳过这一层或阻止该文件；非日期维度不提供文件修改时间选项。          |
| 上移/下移第 N 层 | 调整目录维度顺序，首层不能上移，末层不能下移。                                                                                                |
| 删除第 N 层      | 删除该目录维度。                                                                                                                              |
| + 添加维度       | 新增一个“拍摄日期 / 用文件修改时间”维度；修改为非日期维度后会自动使用“放入未知”。                                                             |
| 目录维度拖动     | 拖动目录维度改变顺序。                                                                                                                        |
| 文件命名模板     | 编辑文件名变量模板。支持 capture_time、camera、lens、original_name、semantic、tone、dominant_color、saturation、sequence、short_hash 等变量。 |
| 缺失元数据时     | 设置命名模板及语义、影调、颜色等字段缺失时的默认策略；“拍摄时间用文件修改时间”只对拍摄时间生效。                                              |
| 重名策略         | 选择添加序号、添加 short hash 或跳过。                                                                                                        |
| 序号起点         | 设置序列起始值，最小为 1。                                                                                                                    |
| 序号宽度         | 设置序列补零宽度，范围 1 到 12。                                                                                                              |
| 生成整理预览     | 校验规则并生成目标目录树、完整源/目标映射和问题清单。目标为空或规则不安全时显示错误。                                                         |
| 导出 JSON        | 通过另存为对话框导出完整 dry-run 计划；拒绝覆盖已有文件。                                                                                     |
| 导出 CSV         | 导出逐文件清单；同样拒绝覆盖已有文件。                                                                                                        |
| 映射行           | 选中一条映射，在右侧查看源路径、目标路径、模板变量和检查结果。                                                                                |

工作区还显示文件、冲突、错误、警告、估算字节数、目标空间未探测提示、目标目录树和完整映射表。当前没有“执行整理”“复制”“回滚”按钮。

## 6. 键盘与无障碍交互

- `G`：切换到多图预览；`F`：切换到单图预览；两者可在设置中调整。
- `Enter`：网格中有活动图片时进入单图预览。
- `Escape`：单图模式返回网格；网格模式清除批量选择。
- `ArrowLeft` / `ArrowRight`：单图模式切换前后图片。
- `0`：清除星级；`1`–`5`：设置星级；`[` / `]`：降低/提高一级星级。
- `6` / `7` / `8` / `9`：设置红/黄/绿/蓝色标；再次按当前已设置的同一快捷键会清除该色标。当前图片属于批量选择集合时，这些操作会应用到整个集合；未选中集合时只作用于当前图片。
- 图片卡片使用 `aria-pressed` 表示活动和选择状态。
- 扫描进度使用 `role="progressbar"` 和数值属性。
- 错误消息使用 `role="alert"`，任务状态使用可读文本。
- 面板、搜索框、排序、筛选、图片网格和胶片栏提供语义化 aria-label。

## 7. 当前安全边界与未开放功能

### 已实现的安全措施

- 扫描和分析只读源图库。
- 缩略图、数据库、模型和日志存储在应用数据目录。
- 扫描、语义分析和整理计划都支持错误隔离或问题诊断。
- 整理规划检查路径越界、非法段、保留名、路径长度、冲突和源文件变化。
- 导出计划使用 `create_new`，不覆盖已有文件，也不允许写入源图库。
- 从图库移除不调用源目录删除、移动或重命名 API。

### 当前明确未开放

- 复制到目标目录的执行动作；
- 移动、重命名、覆盖、永久删除；
- 生成副本后的回滚执行；
- 人脸身份识别；
- 视频和专业 RAW 显影；
- 云同步、远程后端、账号和订阅；
- 模型训练或自动生成描述。

文件复制、操作日志、撤销和恢复的数据表边界已经预留，但前端没有执行命令，不能把整理预览当成实际整理完成。
