# PhotoOrganizer 界面设计规范

## 方向

界面是深色、桌面优先的专业摄影工作台，结构参考 Lightroom 类图片管理软件但不复制品牌、图标或像素细节。图片始终是视觉主体。

新拟物是本阶段的整体视觉语言：使用中性石墨灰表面、同色系高光/暗部双层阴影和一个低饱和灰蓝强调色表达层级。卡片与控件采用明显但克制的圆角；浮层有更深的悬浮阴影，普通按钮和模块不使用无语义的硬描边，改由浮起/按下阴影表达层级。描边只保留给键盘焦点、当前图库、当前图片、选中图片、拖拽目标和人工色标等需要快速识别的状态。人工色标只在图片卡片网格单元使用低饱和度背景和对应色提示，不给原图加色，也不承担唯一的状态表达。禁止米白背景、橙红渐变、发光光斑和依赖颜色才能理解的状态。

## 设计 token

全部 token 统一维护在 `src/styles.css`：

- 应用/画布：`#222222` / `#171717`
- 工具栏/面板：`#2D2D2D` / `#2A2A2A`
- 浮起表面：`#363636`，按下表面：`#1E1E1E`
- 灰阶层级：`--surface-0` 画布、`--surface-1` 面板、`--surface-2/3` 分组卡片、`--surface-control` 操作按钮；相邻层级必须有可辨识的亮度差。
- 边框：普通表面默认透明；仅状态/焦点使用低饱和灰蓝或对应色轮廓。层级优先使用 `--neu-shadow-raised` 与 `--neu-shadow-pressed`。
- 主/次/弱文字：`#EEEEEE` / `#C1C1C1` / `#898989`
- 单一灰蓝强调：`#9EB5C1`，强强调 `#C7D6DC`，仅用于选中、焦点和主要操作
- 圆角：控件 10–12px、卡片 14–18px、空状态 20px
- 字体：`Segoe UI Variable Text`，中文回退 `Segoe UI`、`Microsoft YaHei UI`、`PingFang SC`

不得添加在线字体或大型 UI 框架。正文、边框、键盘焦点必须保持可辨识对比。

## 工作区结构

- 顶部 64px 工具栏：图库名称、数量/扫描状态、网格/单图切换、搜索、筛选、排序、导入、分析。
- 左侧默认 270px：上方独立的“图库”区域承载 Library 树，导入按钮固定在“图库”标题栏右侧，图库节点与标题栏保留明确的顶部留白；只有一个图库时不再额外显示重复的“图库”标题。下方独立滚动的“分类与筛选”区域只承载内容属性筛选；未完成语义分析的状态筛选移到中央图片区域上方，人工标记筛选放在中央预览底栏。面板始终显示，宽度可在 218–420px 之间拖动调整。图库树只展示 PhotoOrganizer 中显式建立的 Library 关系，不展示磁盘目录树。
- 中央：网格、分组网格、单图画布、状态和分页；图片结果底部固定人工标记筛选横栏。卡片只显示文件名、少量传统指标和最多两个标签。
- 右侧默认 320px：文件、EXIF、影调色彩、语义相似度、模型/后端和重新分析；面板始终显示，可在 256–460px 之间拖动调整。
- 左右圆角面板靠近中央画布的外缘承担宽度调整；不显示独立的垂直拖手，拖动只改变布局宽度，不改变图库、图片或源文件数据；键盘仍保留可访问的分隔条语义。
- 单图模式底部固定紧凑胶片栏；网格模式不显示。
- 人工标记筛选横栏在网格模式位于图片结果下方，在单图模式位于主画布和胶片栏之间；两种视图共用同一组星级与色标筛选状态。

宽度 1260px 以下左右面板收窄，1080px 以下工具栏次要操作只保留图标。960×720 是较窄桌面兜底；用户可拖动圆角面板外缘释放或恢复画布空间。页面本身不得横向溢出。

## 状态与语义

- 当前图片同时使用蓝色边框、勾选和 `aria-pressed`，不只依赖颜色。
- 单图模式必须保留当前图片的“选择/取消选择”入口；胶片栏同时区分当前图片和选择集合，避免只导航图片却无法参与批量操作。
- Lightroom 风格的星级和色标操作固定在卡片底部的单元内部；不使用会脱离卡片的浮动工具条，也不因显示数字而改变分类模块或网格卡片高度。
- 人工标记筛选作为中央预览底部的紧凑横栏提供，不嵌入左侧分类面板；星级为单一“该星级及以上”阈值选择，色标支持多选，清除入口只在存在筛选时出现。
- 左侧分类筛选按钮采用紧凑芯片尺寸；保留清晰的文字、计数、悬停、按下和选中状态，避免单个计数变化导致模块高度跳动。图库存在未完成语义分析时，中央图片区域上方显示紧凑的“分析状态”筛选条；没有未完成分析时不占用空间。
- 色标生效时，网格单元仅使用低饱和度的对应背景/边框提示；缩略图本身保持原样。批量选择后从任意选中卡片操作，会同步应用到整个选择集合。
- 按钮必须有明确的浮起、悬停、按下、选中、禁用和键盘焦点状态；按下时使用内阴影和轻微下沉，悬停时只允许轻微抬升。
- 普通按钮、筛选芯片和模块不应通过成片的 1px 亮边分隔；同一层级优先共享表面色和阴影，避免“每个元素都有一圈线”。
- 可变的筛选计数徽标必须预留固定尺寸；从未选中到选中只改变内容和可见性，不得改变分类模块高度或推动下方模块。
- 语义分值必须写“相似度”，右侧明确说明不是概率或准确率。
- 模型未就绪时不显示假标签；按钮显示准备模型，基础图库保持可用。
- 任务条显示真实 processed/total、失败数和实际 backend，并提供暂停/继续/取消。
- 错误使用文字与 `role=alert`；进度使用原生可访问名称和数值。

## 视觉验收

检查 1920×1080、1440×900、1366×768 和 960×720：

- 页面 `scrollWidth` 不大于 viewport，工具栏不横向溢出；
- 网格列稳定变化，长中文/Unicode 文件名省略；
- 左右面板始终显示，内容区域独立滚动；
- 左侧图库区与分类筛选区使用两个独立的圆角矩形模块并分别滚动；模块内部筛选组保持扁平，避免重复凹陷；左右圆角面板靠近中央画布的外缘可拖拽，最小/最大宽度生效；
- 右侧信息模块使用单层层级：外层圆角模块负责浮起，导航图、分析指标等实际内容井最多凹入一次，不叠加相同的内阴影；
- 顶部工具栏提供白天/深色主题切换。白天模式使用浅灰层级而非纯白，蓝色只承担选中、焦点和主要操作语义；人工色标保留其原有颜色。
- 人工标记筛选横栏在网格和单图预览中都位于中央内容底部，且不进入左侧分类面板；
- 单图画布和胶片栏同时可见；
- 组合筛选后的数量、卡片和主要标签分组一致；
- 键盘焦点、空/加载/扫描/错误/模型不可用状态清晰。

开发预览通过 `?visual-fixture=library|scanning|error` 使用确定性数据，不访问 SQLite 或个人图库；生产构建通过 `import.meta.env.DEV` 排除该模块。当前里程碑截图位于 `docs/screenshots/semantic-*.png`。
