# PhotoOrganizer 界面设计规范

## 方向

界面是深色、桌面优先的专业摄影工作台，结构参考 Lightroom 类图片管理软件但不复制品牌、图标或像素细节。图片始终是视觉主体。

新拟物是本阶段的整体视觉语言：使用冷灰蓝表面、同色系高光/暗部双层阴影和一个低饱和蓝色强调色表达层级。卡片与控件采用明显但克制的圆角；浮层有更深的悬浮阴影，选中/按下状态使用内阴影和蓝色边缘共同表达。禁止米白背景、橙红渐变、发光光斑和依赖颜色才能理解的状态。

## 设计 token

全部 token 统一维护在 `src/styles.css`：

- 应用/画布：`#222222` / `#171717`
- 工具栏/面板：`#2D2D2D` / `#2A2A2A`
- 浮起表面：`#363636`，按下表面：`#1E1E1E`
- 边框：`rgba(255, 255, 255, 0.14)`，次边框 `rgba(255, 255, 255, 0.08)`
- 主/次/弱文字：`#EEEEEE` / `#C1C1C1` / `#898989`
- 单一灰蓝强调：`#9EB5C1`，强强调 `#C7D6DC`，仅用于选中、焦点和主要操作
- 圆角：控件 10–12px、卡片 14–18px、空状态 20px
- 字体：`Segoe UI Variable Text`，中文回退 `Segoe UI`、`Microsoft YaHei UI`、`PingFang SC`

不得添加在线字体或大型 UI 框架。正文、边框、键盘焦点必须保持可辨识对比。

## 工作区结构

- 顶部 64px 工具栏：图库名称、数量/扫描状态、网格/单图切换、搜索、筛选、排序、导入、分析。
- 左侧默认 270px：图库树、更多筛选、主类别、辅助标签、影调、饱和度级别、主色、亮度/饱和度/日期范围；可折叠为 54px。图库树只展示 PhotoOrganizer 中显式建立的 Library 关系，不展示磁盘目录树。
- 中央：网格、分组网格、单图画布、状态和分页。卡片只显示文件名、少量传统指标和最多两个标签。
- 右侧默认 320px：文件、EXIF、影调色彩、语义相似度、模型/后端和重新分析；可折叠为 54px。
- 单图模式底部固定紧凑胶片栏；网格模式不显示。

宽度 1260px 以下左右面板收窄，1080px 以下工具栏次要操作只保留图标。960×720 是较窄桌面兜底；用户可折叠左右面板释放画布。页面本身不得横向溢出。

## 状态与语义

- 当前图片同时使用蓝色边框、勾选和 `aria-pressed`，不只依赖颜色。
- 按钮必须有明确的浮起、悬停、按下、选中、禁用和键盘焦点状态；按下时使用内阴影和轻微下沉，悬停时只允许轻微抬升。
- 语义分值必须写“相似度”，右侧明确说明不是概率或准确率。
- 模型未就绪时不显示假标签；按钮显示准备模型，基础图库保持可用。
- 任务条显示真实 processed/total、失败数和实际 backend，并提供暂停/继续/取消。
- 错误使用文字与 `role=alert`；进度使用原生可访问名称和数值。

## 视觉验收

检查 1920×1080、1440×900、1366×768 和 960×720：

- 页面 `scrollWidth` 不大于 viewport，工具栏不横向溢出；
- 网格列稳定变化，长中文/Unicode 文件名省略；
- 左右面板可折叠，展开后信息可滚动；
- 单图画布和胶片栏同时可见；
- 组合筛选后的数量、卡片和主要标签分组一致；
- 键盘焦点、空/加载/扫描/错误/模型不可用状态清晰。

开发预览通过 `?visual-fixture=library|scanning|error` 使用确定性数据，不访问 SQLite 或个人图库；生产构建通过 `import.meta.env.DEV` 排除该模块。当前里程碑截图位于 `docs/screenshots/semantic-*.png`。
