### 安全恢复补丁

补丁针对基线 `85844fd` 的五个目标路径生成。应用前核对这些路径的基线 SHA-256：三个已有文件必须与上表完全相同，两个新增路径必须不存在。HEAD 可以是本交接提交，或其后仅包含交接文档和补丁行尾属性的提交；这些提交不得改动五个源码路径。只要有任一源码路径不符就停止。核对通过后运行：

```powershell
git apply --unidiff-zero --check docs/handoff/export-recovery-wip.patch
git apply --unidiff-zero docs/handoff/export-recovery-wip.patch
```

零上下文补丁只适用于完全相同的基线。任何基线哈希不符、目标文件已存在、检查失败或应用后目标 SHA-256 不符，都应停止并重新审查；不要 trim/改写补丁，也不要使用忽略空白选项。只允许得到表中五个路径。用仅含五个基线文件的 archive 做隔离验证时，需设 `core.autocrlf=false`，因为 archive 不含仓库属性文件；本次隔离应用已用该设置逐文件得到与表中 WIP 目标相同的物理 SHA-256。真实 clone 由仓库属性约束为 LF。

补丁文件本身要求物理字节和 Git index/commit blob 一致。仓库新增的 `docs/handoff/*.patch text eol=lf` 规则固定其 checkout 行尾。暂存交接文件后，用 Node 比较工作树与 index blob；提交后也可把 ref 改成 `HEAD:docs/handoff/export-recovery-wip.patch`：

