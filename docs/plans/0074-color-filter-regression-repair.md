# 0074 颜色筛选回归修复

状态：实现与针对性验证完成，等待主代理审查

## 目标与边界

恢复色相范围筛选对真实颜色的区分能力，降低中性灰白、低彩度白平衡偏色及近中性肤色被识别成蓝/橙强调色的情况；避免面积与显著性候选重复抬高命中。保留现有色轮手势模型、色相角度约定、应用私有缩略图输入、离线实现与既有调色板结构。只修改本计划、`imaging.rs`、`db.rs`、`ColorRangeFilter.tsx`、其测试、`colorFilter.ts`、其测试、`types.ts`，必要时更新当前功能文档与 `docs/testing.md`。

## 调查结论

- `230ffea` 将旧版 12 桶直方图筛选替换为连续色相候选：旧版以有色像素为分母，目标色约 8%–75% 即可命中；新版按全图面积要求 8%–45%，默认严格度 0.5 对应 26.5%。这会漏掉只占部分画面、但肉眼显著的颜色。色轮角度映射不是此次回归根因，且该提交未修改 `imaging.rs`。
- 像素强调色阈值原为 `MIN_ACCENT_CHROMA=0.0085`。Oklab 色度约 `0.009` 的冷灰 `[180,185,190]`、暖灰 `[175,170,165]` 因而会进入蓝/橙分类；Oklab 色度约 `0.067` 的低饱和肤色 `[223,178,148]` 也处于旧强调色区间。修复统一按 RGB 推导 Oklab 色度，将常规下限设为 `0.035`，并对明度中等、橙色区间且色度低于 `0.08` 的肤色样暖色提高门槛；DB 对缺少 `chroma` 的旧 JSON 从 RGB 推导，而不是一概降为中性。
- 色轮 CSS 色谱从正上方 0° 顺时针，与 `angleFromEvent` / `pointAt` 的正弦映射一致。修复前用显式坐标测试覆盖 0° 邻接、跨 0° 范围和弧/端点动作锁定；没有证据时不重写映射。
- 颜色重新分析由 `scanner.rs` 比较 `imaging::ANALYSIS_VERSION` 决定；提升该版本会重用现有应用缩略图重算基础特征。语义模型有独立版本，计划不更改它。

## 实施步骤

1. 为成像器增加合成缩略图回归：中性灰白、白平衡冷暖偏色、低饱和肤色、柔和蓝色与橙叶/棕木正例、实色、多色、显著色块及灰底孤立像素；强调色必须过最小面积门槛。
2. 为数据库谓词和实际查询 fixture 增加回归：近色与跨 0° 可通过、远色不通过；高严格度要求面积主色命中；显著小色块在合理严格度下可命中；重复覆盖/强调候选不重复放大面积或显著性。
3. 校正全图面积门槛至 4%–32%（默认 18%），强调色辅助仍有上限；保证严格度单调、低色度候选不贡献面积，并同步 `colorFilter.ts` 文案/类型注释与 `docs/testing.md`。
4. 为色轮建立明确的指针坐标用例，覆盖 0°、359° 相邻方向、跨零范围及拖弧旋转/拖端点调宽，确认同一按下动作不切换。
5. 将 `ANALYSIS_VERSION` 与颜色算法版本一并递增，令已有扫描图库只重算基础颜色/影调特征；不改变语义分析版本或模型任务。
6. 更新用户可见功能文档；审阅 diff 后运行相关 Rust 测试与 Clippy、前端受影响 Vitest、lint、typecheck、格式及 `git diff --check`。记录未跑项和可能的重扫耗时。

## 验收

- 灰、白、低彩度冷暖偏色及低彩度肤色色块不再广泛作为蓝/橙强调色；低彩度色偏不触发大范围色相命中。
- 大面积纯色、多色照片和有足够覆盖/显著性的较小色块在合理严格度下可筛出；高严格度的 UI 主色必须匹配目标色相。
- 连续角度处理邻近色及 0°/360° 环绕一致；色轮弧与端点的行为由命中动作决定并在拖动期间保持锁定。
- 候选重复、候选面积或显著性值异常时不会重复计入；列表分页总数与筛选结果共享谓词。
- 重扫使用缓存缩略图重算基础颜色，不触发语义模型版本更新。
