# 0063 摄影题材与主体标签精简

状态：实现完成，自动校验完成，待桌面端人工验收

## 目标

把自动分类收敛为摄影师实际会使用的短标签，避免把 Places365 的场景桶、物体检测类别和摄影题材混在同一组筛选项中。

本次只调整分类词典、模型输出映射、读取兼容和筛选目录，不改变文件来源、图库/收藏夹模型、整理导出或缩略图-only 处理边界。

## 用户可见的现行标签

### 拍摄题材（主类别，互斥）

| 稳定 ID              | 中文名称 |
| -------------------- | -------- |
| `photo_portrait`     | 人像     |
| `photo_landscape`    | 风光     |
| `photo_street`       | 街拍     |
| `photo_architecture` | 建筑     |
| `photo_still_life`   | 静物特写 |
| `photo_wildlife`     | 动物     |
| `photo_macro`        | 植物     |
| `photo_vehicle`      | 交通工具 |
| `photo_abstract`     | 抽象艺术 |

主类别仍只选择一个。没有达到当前阈值或候选间隔不足的结果统一落到抽象艺术；界面不再新增“未知”、纪实与工业、餐饮与商业、运动活动等宽泛题材。

### 主体标签（可并存）

`单人`、`多人`、`动物`、`植物`、`食物`、`风景`。

单人和多人互斥；动物、植物、食物可以与人物或风景并存。 `风景` 不是 PicoDet/YuNet 的物体检测结果，而是高置信 `风光` 题材在语义层派生的主体证据，因此保存于 `semantic_labels`，不伪装成 `subject_labels` 的检测框结果。

## 实现边界

1. `src-tauri/src/topics.rs` 使用 SigLIP 2 的多提示词候选，题材 taxonomy 升级为 v4，并只保留九个摄影题材。
2. `src-tauri/src/subject.rs` 的主体 taxonomy 升级为 v3，PicoDet/YuNet 只输出五个直接主体标签；移除车辆主体标签，车辆只作为摄影题材。
3. `src-tauri/src/semantic_tasks.rs` 在高置信风光结果上追加非主类 `scenery/风景` 语义证据，并保持直接主体融合：人物、动物、植物、食物仍可改善主类候选，但不会把主体标签改写成题材列表。
4. Places365 仅提供辅助场景证据。可映射的场景证据收敛到风光、街拍、建筑、静物特写、交通工具和植物；工业、活动、室内、旅行等不再强行变成摄影师题材。
5. `src/classificationLabels.ts` 的筛选和编辑选项只展示九个题材、六个主体标签。旧值通过 canonical mapping 读取为当前标签，旧值不会重新出现在新选项中；上下文 `室内/室外` 仍可作为内部证据，但不进入主体筛选。

## 兼容与迁移

- 现有数据库记录不删除。读取边界把 `unknown`、纪实/活动/文档等旧题材归并为 `photo_abstract`，食品/商业归并为 `photo_still_life`，城市、交通、植物和旧人物别名归并到对应新 ID。
- 新分析使用 v4/v3 taxonomy；旧版本结果不会被误认为新版本分析完成，用户可通过重新分析获得新标签。
- 历史整理规则和人工覆盖继续可读，但新增编辑和筛选不接受旧标签作为新选择项。

## 校验与验收

- Rust：题材 ID、名称、互斥选择、旧 ID 归并、Places365 映射、主体目录和风景派生证据测试。
- 前端：题材/主体选项精确集合、旧标签兼容显示、筛选目录不暴露环境和历史宽泛标签测试。
- 工程检查：`cargo fmt --all -- --check`、`cargo test --all-targets`、前端全量测试、typecheck、lint、build。
- 桌面验收：重新分析一组混合照片，确认题材只出现九项；主体标签只出现六项；风光照片可出现风景；旧数据库中的未知/食品/宠物仍能正常显示为当前名称；筛选数量与卡片结果一致。

## 后续风险

标签名称精简不会自动提升模型质量。真正的逐类 precision/recall 和阈值校准仍需要用户授权的真实摄影评测集；在此之前不把相似度显示为概率，也不把一次分类结果视为绝对事实。
