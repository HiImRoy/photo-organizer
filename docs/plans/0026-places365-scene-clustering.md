# Places365 场景证据与摄影题材重构计划

## 目标

将当前基于 TinyCLIP 自由提示词的分类替换为 Places365 场景证据，并将官方 365 个叶子场景映射为稳定、互斥、贴近个人摄影工作流的中文“拍摄题材”。

Places365 只负责图片所处的场景/环境，不承担人物、动物、车辆或花卉主体识别。人物/人像将作为后续独立的本地主体模型能力，与拍摄题材并列展示。

## 范围

- 使用 Places365 ResNet-18 的 365 类输出作为叶子证据。
- 将 365 个叶子标签映射到 11 个互斥摄影题材：风光自然、城市街拍、建筑与空间、美食餐饮、商业与静物、室内与生活、旅行人文、活动与运动、交通与汽车、植物与园艺、纪实与工业。
- 从原始 Places365 宽泛场景桶中显式拆出美食、旅行、植物相关叶子，使界面更贴近摄影师的拍摄主题。
- 以题材聚合概率选择一个主类别；低置信度或无明显优势时使用虚拟状态“未知”，不把“未知”作为模型候选类别。
- 保存模型版本、taxonomy 版本和源指纹；新 taxonomy 不读取旧 taxonomy 的自动标签，需重新分析才能生效。
- 前端显示全部使用中文；英文 Places365 叶子 ID 只作为内部稳定 ID/调试证据，不直接显示在图库界面。
- 保留 TinyCLIP 的本地文本/图像向量能力，作为兼容路径和后续相似搜索能力，不再把自由提示词结果作为新的拍摄题材。

## 当前 11 个摄影题材

| 内部 ID | 中文名称 | 归类原则 |
| --- | --- | --- |
| `photo_landscape` | 风光自然 | 山水、海岸、森林、天空、荒野，以及未细分的田野和户外景观 |
| `photo_urban` | 城市街拍 | 街道、社区、广场、城市公共空间 |
| `photo_architecture` | 建筑与空间 | 建筑立面、桥梁、地标、宗教与历史建筑 |
| `photo_food` | 美食餐饮 | 餐厅、咖啡厅、厨房、市场食品、宴会与菜品场景 |
| `photo_commercial` | 商业与静物 | 商店、橱窗、商场、展售空间、沙龙与商业陈列 |
| `photo_indoor` | 室内与生活 | 家居、办公室、学校、医院、公共室内和日常生活空间 |
| `photo_travel` | 旅行人文 | 机场、车站、港口、酒店、博物馆、艺术空间和旅行设施 |
| `photo_event` | 活动与运动 | 体育场馆、演出、娱乐、游乐园和活动现场 |
| `photo_transport` | 交通与汽车 | 汽车、车库、道路、停车场、铁路和交通设备 |
| `photo_plant` | 植物与园艺 | 植物园、花园、温室、果园、农田和园艺场景 |
| `photo_documentary` | 纪实与工业 | 工业、施工、能源、维修、军事和工作现场 |

合计覆盖 365 个官方叶子类别。`unknown` 是拒识结果，不计入 365 类。Places365 叶子 ID 和概率保存在语义证据表中，界面不直接展示英文叶子名。

## 人物主体模型边界

Places365 不负责判断“是否有人”“单人/多人”或“是否为人像”。后续主体模型应独立输出多标签结果，并与拍摄题材并列：例如一张街拍可以同时拥有“城市街拍 + 单人 + 夜景”。第一阶段只保留清晰的模型边界，不把人物结果写进主类别。

## 不在本阶段

- 不训练新模型。
- 不使用 K-Means 对每次图库结果动态聚类；类别定义必须稳定，避免同一图片在不同图库中出现不同主类别。
- 不把人物、车辆、动物、花卉等主体标签硬塞进 Places365 场景主类别。
- 不修改原始照片、不写回 EXIF、不引入云端服务。

## 验收标准

1. 365 个官方 Places365 叶子标签全部被覆盖，且每个叶子只属于一个摄影题材。
2. 分类筛选界面展示“拍摄题材”和中文名称，主类别选择互斥。
3. 题材聚合概率、第一名与第二名差值、拒识阈值有自动化测试。
4. 旧数据库仍可打开；旧自动标签不会与新 taxonomy 混合，人工覆盖仍可读取和恢复。
5. 模型缺失时软件仍能启动，状态栏明确显示本地语义模型未就绪，不回退到错误的旧标签结果。
6. 完成 Rust 测试、前端测试、类型检查、构建检查，并记录模型资源来源、哈希和许可证。
