# PhotoOrganizer 整理预览（Dry-run）里程碑计划

- 状态：待实施
- 创建日期：2026-08-07
- 前置条件：语义工作区发布基线、正式数据库迁移和 Windows CI 打包通道稳定
- 范围：只生成可审查的目标目录与文件名计划；不执行任何文件复制、移动、重命名、覆盖或删除

## 目标

让用户选择一个与源图库分离的目标根目录，组合虚拟分类和元数据形成目录层级及命名模板，在内存与 SQLite 中生成确定性的 dry-run 清单。用户可以逐项检查源路径到目标路径的映射、冲突、安全问题和空间估算，并导出清单；本阶段没有“执行计划”按钮或任何写入目标目录的后台任务。

## 强制安全边界

- 原图、源目录、EXIF/XMP 永远只读。
- dry-run 只计算路径字符串和统计信息，不创建目标目录或目标文件。
- 禁止调用 `copy`、`rename`、`move`、`remove`、覆盖写入或回收站 API。
- 目标根目录必须由用户明确选择，不保存任何个人绝对路径到仓库、日志夹具或默认配置。
- 源和目标规范化后不得相同；目标不得位于单个源文件路径之内。目标位于图库根目录内部时默认阻止并解释风险。
- 导出清单是本阶段唯一允许的写操作，必须使用另存为对话框、拒绝覆盖已有文件，并且不写入源图库。
- 所有自动化测试只使用 `test-data/` 或临时目录，且前后校验源文件哈希。

## 用户流程

1. 从专业工作区进入“整理预览”。
2. 选择目标根目录；界面明确标注当前仍是 dry-run。
3. 从受支持字段中添加、删除并拖动目录层级顺序。
4. 编辑文件命名模板并查看即时示例。
5. 选择图片范围：当前筛选结果、当前选择或整个图库。
6. 生成只读目标树和源到目标映射。
7. 检查冲突、非法字符、路径长度、缺失元数据和磁盘空间提示。
8. 调整规则并重新生成；旧计划标记为过期，不与新计划混合。
9. 导出 JSON/CSV dry-run 清单；不提供真实执行入口。

## 第一版目录层级

候选层级组件：

- 拍摄年、月、日；
- 主要语义标签；
- 影调；
- 主色分类；
- 原始相对目录；
- 固定文本段。

层级是有序数组，每项拥有稳定 `kind`、参数和缺失值策略。拖动只改变数组顺序。空层级允许把全部计划文件直接放在目标根目录，但仍执行命名和冲突检查。

## 文件命名模板

第一版变量候选：`{original_stem}`、`{extension}`、`{captured_date}`、`{captured_time}`、`{primary_label}`、`{tone}`、`{dominant_color}`、`{sequence}`、`{short_hash}`。

模板解析器必须：

- 拒绝未知变量和未闭合语法；
- 保留原扩展名并规范化大小写策略；
- 对 Windows 非法字符 `< > : " / \\ | ? *`、控制字符、尾随空格/句点和保留名进行检查；
- 不自动吞掉错误。可预览的替换建议与实际计划值必须分别显示；
- 序号位数和起始值显式配置；同一输入和规则生成稳定结果。

## 缺失元数据回退

每个可缺失字段必须选择明确策略：使用文件修改时间、使用固定文本 `未知`、跳过该层级、使用原始目录或把该项标为阻塞错误。不得静默使用当前系统时间。报告统计每种回退的使用次数并允许定位对应图片。

## 冲突与路径检查

生成计划时一次性检查：

- 多个源文件映射到同一目标路径；
- 目标路径与磁盘上已有文件或目录冲突；
- 大小写不敏感和 Unicode 规范化后的碰撞；
- Windows 保留设备名与非法字符；
- 单段长度和完整路径长度预算；
- 目标逃逸（`..`、绝对模板片段、目录分隔符注入）；
- 源/目标同路径和目标位于源图库内部；
- 计划生成后源 fingerprint 变化导致的过期状态。

冲突状态使用稳定代码，不只保存本地化文案。第一版只报告和定位问题，不自动改名；序号或短哈希只能由用户在模板中明确选择。

## 磁盘空间估算

按计划资产的当前文件大小求和，单独显示总源字节数、目标卷可用空间、保守余量和无法读取大小的数量。估算不能被描述为保证值；若目标卷不可查询或余量不足，计划保持可浏览但标为阻塞导出警告。不得通过创建探测文件来判断权限或空间。

## 数据模型草案

下一 migration 只新增表，不修改 `0001`/`0002`：

- `organization_plans`：图库、目标根目录、规则 JSON、来源筛选快照、状态、创建/更新时间；
- `organization_plan_items`：源 asset、源 fingerprint、相对目标路径、预计字节数、顺序和状态；
- `organization_plan_issues`：稳定问题代码、严重度、路径字段和可选详情。

计划项只保存预览数据。不得新增 executed/copying/moving/deleting 状态，也不得复用 `file_operations` 形成虚假执行记录。目标绝对路径属于本地用户数据，只进入 SQLite，不进入 telemetry 或仓库夹具。

## 服务与 IPC 草案

- `validate_organization_rules`：只解析和验证规则。
- `preview_organization_plan`：基于 SQLite 查询结果生成计划并返回摘要。
- `get_organization_plan`：分页读取目标树和映射。
- `list_organization_issues`：按类型和严重度筛选问题。
- `export_organization_manifest`：在用户明确选择的新文件中导出 JSON/CSV，拒绝覆盖。
- `discard_organization_plan`：只删除应用数据库中的预览记录，不接触源或目标文件系统。

所有 API 名称使用 `preview`、`validate` 或 `export_manifest`，避免出现会暗示已执行文件操作的含糊名称。

## 界面草案

- 左侧：范围、目标根目录、可排序层级、命名模板和回退策略。
- 中央：可折叠目标目录树、文件计数和空间摘要。
- 右侧：选中计划项的源路径、目标路径、变量展开过程和问题列表。
- 顶部持续显示“只读预览 · 不会复制或移动文件”。
- 问题筛选支持冲突、非法名称、过长路径、缺失元数据、空间不足和源已变化。
- 没有执行、复制、移动、应用或确认整理按钮。

## 验收标准

1. 可以选择目标根目录但不会创建任何目录。
2. 可以调整目录层级顺序和命名模板。
3. 可以预览完整目标树与逐项源到目标映射。
4. 组合筛选范围的总数与计划项数量一致。
5. 可以定位重名、非法字符、路径过长、缺失元数据和空间风险。
6. 相同输入、fingerprint 和规则生成字节级稳定的清单。
7. 导出 JSON/CSV 使用新文件且拒绝覆盖。
8. 测试前后源目录和目标目录树、原图字节与哈希完全不变。
9. 产品界面没有真实复制、移动、重命名或删除入口。

## 明确不在本里程碑

真实复制、移动、重命名、覆盖、删除、回收站、回滚执行、并发文件传输、冲突自动改名、创建目标目录、写入 EXIF/XMP、监听目标目录、云端同步和发布后自动整理全部延期。下一阶段完成评审前，不得把 dry-run 计划连接到现有或新增文件操作执行器。
