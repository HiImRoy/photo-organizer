# 执行计划 0025：Semantic Taxonomy 与拒识状态重构

状态：执行中（Checkpoint D）

## 目标

把当前把所有语义结果压进“主类别 / 辅助标签”两栏的实现，收敛为可解释的分组分类契约：

- `scene`：互斥的场景类别，同一张图片最多保留一个有效场景；继续映射到旧的 `primary_category` 字段，保证现有手动编辑、组织预览和导出变量兼容。
- `subject`：可同时成立的主体标签，例如车辆、花卉、山、水体、森林。
- `context`：可同时成立的环境属性，例如室内、街道、夜景、日落。
- `other`：明确的场景兜底类别，但只有通过自身阈值和组内间隔检查才可产生。
- `unknown`：不再作为模型 prompt 或竞争候选；分析成功但没有可靠 `scene` 结果时，由解析层生成的拒识状态。
- `failed`：推理或持久化失败，继续由 `semantic_status` 表示，不伪装成 `unknown`。

## 约束与兼容策略

1. 不替换 TinyCLIP，不新增生产依赖；先修复候选集合、阈值、组内选择和数据契约。
2. 新增 taxonomy 版本和标签分组字段采用向前兼容的 SQLite migration；旧结果不会被解释为新 taxonomy，重新分析后才进入新契约。
3. `is_primary` 仅表示 `scene` 组的兼容主类别，不再代表“所有重要标签”。新的 `category_group` 才是业务语义来源。
4. 未知状态不落成一个模型相似度分数；界面和筛选通过“已完成但没有有效 scene 行”识别它。
5. 当前阶段先完成运行时与消费链路；评估数据集和阈值校准作为 D 的后续 gate，不把未经验证的分数宣称为准确率。

## 实施顺序

1. 增加 taxonomy 版本、组别元数据和 0012 数据库迁移。
2. 移除 `unknown` prompt，启用细分的历史标签，重写按组选择逻辑。
3. 让保存、读取、复制、有效分类、分组计数和筛选都使用当前 taxonomy；为 `unknown` 增加虚拟拒识筛选。
4. 更新 React 类型、侧栏分组、详情状态文案和测试 fixture。
5. 更新 D 文档，运行 Rust/前端格式、lint、类型、单元测试与构建。

## 暂不在本次范围

- 更换 SigLIP/CLIP 模型或重新训练模型。
- 人脸身份识别、云端推理和原图写回。
- 通过少量手工样本直接宣称阈值已经完成生产级校准。

## 验收证据

- `unknown` 不出现在 `raw_similarities`，低置信度完成结果没有伪造的 UNKNOWN 模型分数。
- 每个成功结果最多一个 `scene`/兼容 primary，subject/context 可多选。
- FAILED 没有自动分类结果，手动覆盖仍可独立生效。
- 旧数据库可迁移到 0012；旧结果在重新分析前不会错误混入新 taxonomy。
- Rust 与前端测试、lint、typecheck、build 通过。
