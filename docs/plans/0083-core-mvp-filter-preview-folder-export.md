## 结论

把“筛照片、看照片、确认去向、复制原文件”做成一条可靠流程。用户能看到筛选总数、逐项预览目标位置，并确认后复制到一个新文件夹。原有照片始终只读。

本轮不改界面外观、不扩展 AI 功能、不新增依赖，也不把设计稿写成已完成的功能。

## 用户流程

### 1. 筛选并选择照片

用户选择来源并组合条件，界面显示“全部匹配 M 张”。用户可以操作“选中 N 张”或明确选择“全部匹配”。换筛选条件或来源会清除选中项，继续加载下一页不会清除。query 计数、全量分组、membership 与相邻项读取使用后端完整结果，不把已加载页面当成批量范围。

### 2. 查看照片并确认去向

用户在网格中打开单张照片，也可切换胶片栏或比较最多四张。某张照片加载失败时，其它照片仍可查看并可单独重试。进入导出预览后，用户能逐项检查完整目标目录和文件名。

### 3. 复制到新文件夹

用户选择现有父目录和一个新的文件夹名，选择组织方式并确认预览后，应用逐项复制原文件。新建目录下默认保留来源相对目录和原文件名；也可选择来源命名空间或按拍摄年月（年/月/原文件名）归档。

例如三张照片中，两张来自不同来源但都叫 IMG_1042.jpg，另一张没有拍摄日期。默认保留来源相对目录和文件名；如果映射产生同一目标，预览会显示冲突，用户可选择来源命名空间或其它受支持的冲突方式。如改用年月归档，缺少日期的照片必须先选择明确去向。目标命名冲突默认阻止开始；用户可在预览时选择添加序号、短标识或跳过，并再次确认清单。取消后已完成项保留；任务重启后先核对状态，不自动删除残留文件。

## 必须遵守的规则

- 不同筛选条件可以组合；界面分别显示“选中 N 张”和“全部匹配 M 张”。
- 更换来源或筛选条件会清除选择；单纯追加下一页会保留选择。
- 缺少拍摄日期时不偷偷改用文件修改日期；筛选和目录整理各按明确选择处理。
- 默认保留原目录与原文件名；按拍摄年月是可选整理方式。
- 原文件只复制，不改写、不移动、不覆盖。确认前必须显示最终目录和文件名。
- 同名冲突必须在预览中选择处理方式；执行中遇到新冲突就停止该项，不临时改名或覆盖。
- 导出范围包含多个来源时，目录中增加来源区分层；单一来源不增加该层。
- 取消保留已完成项；进程重启先核对，不自动重放任务或删除文件。
- 撤销仅针对本任务创建、身份与内容仍匹配的副本；绝不删除原图或递归删除目录。
- 编辑预览与 recipe 保存可用；旧的全尺寸编辑派生导出和 legacy rollback 入口保持禁用并说明原因。

## 技术选型

| 选择                                   | 原因                                             |
| -------------------------------------- | ------------------------------------------------ |
| 沿用现有桌面应用、本地数据库和前后端   | 不更换架构，不新增依赖或服务。                   |
| 复制原始文件内容，不重新编码           | 保留原文件字节和内嵌信息；不会生成新的图像版本。 |
| 一次处理一个文件，分段读写             | 限制内存使用；可以在文件间或数据块边界检查取消。 |
| 先保存完整预览与操作记录，再开始写文件 | 失败后可说明哪些项目完成、失败或待核对。         |

## 完成标准

- [ ] 条件组合、筛选总数、分组计数和跨页选择一致。
- [ ] 网格、单图、胶片栏、四图比较、编辑预览和目录预览都能显示加载与错误状态。
- [ ] 用户能在执行前核对每张照片的最终目录、文件名和冲突处理方式。
- [ ] 复制后原文件内容未变，目标文件内容与来源一致；任何目标都不会被覆盖。
- [ ] 取消、断电/重启、权限不足和磁盘空间不足均留下可解释的任务状态；不自动清除未知文件。
- [ ] 撤销只处理本任务创建且身份和内容匹配的副本。
- [ ] 测试覆盖中文、空格、Unicode 路径与来源变化；所有文件操作只使用测试夹具或测试临时目录。
- [ ] 高分辨率 fixture 覆盖 import/analysis/model/decode 边界，确认不会创建 full-resolution source pixel buffer。
- [ ] 深浅主题与窄桌面宽度下，邻接按钮共享圆角及几何；左导航 rail 外壳保持透明、无边框。

## 限制与未包含内容

本地隔离流程已从两个来源的真实扫描运行到 plan、copy 与 rollback，测试确认来源文件未改变；rollback preview 后目标被篡改时执行也会拒绝。高分辨率 thumbnail 边界与 recovery targeted tests 通过；directory junction reparse 拒绝已由真实 Windows fixture/handle identity 定向测试验证。这些不是发布或桌面验收。最终前端 175 tests、lint/typecheck/build 已通过。后端 all-target Rust 复跑为 216/217，唯一失败为 `semantic_tasks` Windows file symlink 创建报错 1314；该环境错误未被跳过，仍待处理。`cargo fmt`、clippy 与 desktop build 已通过。规范启动与隔离路径下 `-CheckOnly` 已通过，但完整桌面交互尚未验收。在 Recovery Gate 最终验收前，不得将 Safe Copy 标为已验收。ADR-0015 已接受并将旧的“完整 N3 产品先完成”路线图门禁缩小为该最小门槛；完整备份与恢复功能仍未纳入本方案，详见 ADR-0015 与技术附录。

Places365 categories 文件的哈希差异已诊断为预期值记录了 CRLF 变体，而固定上游版本、HEAD blob 与工作树均为规范 LF 字节；校验脚本现按实际字节验证，未做行尾归一化。本次 `verify-release-resources.ps1` 全量资源检查通过；这只是资源合同检查，不代表功能验收或 CI 发布通过。完整证据见[本机接收记录](../handoff/2026-10-19.md)。

本轮不修改界面外观，不扩展 AI 分类或新功能。现有图像导入、分析及模型处理仍须遵守缩略图边界；原图像素只允许在当前查看器中由用户明确请求原尺寸预览。
