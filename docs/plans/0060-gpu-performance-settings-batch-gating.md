# 0060 GPU 性能优化：设置与批大小门控

**状态：已实现；S1/S2 自动化门禁通过，保留为阶段记录。**

## 范围

本阶段完成 GPU Provider 接入前的低风险准备工作，不改变当前模型推理后端：

- 设置页持久化“启用 GPU 加速”选项；
- 分析批大小配置范围扩大为 1–32；
- 当前 DirectML Provider 未就绪时，实际分析批大小强制限制为 8；
- 只有 DirectML 状态为 `ready` 且用户启用 GPU 加速时，才允许进入 1–32 的配置范围；实际有效上限由 S2 的专用显存分级决定；
- 图库批量分析和单图重新分析共用同一有效批大小计算；
- GPU 开关在 Provider 未就绪时保持禁用，不产生虚假加速状态。

## 明确不在本阶段

- 不加载 DirectML/CUDA Provider；
- 不替换当前 CPU ONNX Runtime DLL；
- 不调整导入 worker、任务并发或缩略图解码边界；
- 不把检测到独立 GPU 当作 Provider 已初始化；
- 不宣称当前分析已经使用 GPU。

## 为什么先做门控

批大小增大可以提高已验证 GPU Provider 的吞吐，但在 CPU 后端上会增加同时存在的缩略图张量和模型中间结果，可能造成内存峰值和界面卡顿。因此配置上限与实际运行上限分离：用户可以提前保存目标值，任务只使用当前已经通过 Provider 自检的上限。

DirectML 的实际接入仍需随包提供 DML-enabled ONNX Runtime、会话初始化、自检、输出一致性、失败回退和安装包 smoke。ONNX Runtime 官方文档也要求通过对应 execution provider 注册并准备匹配的运行时资源。

## 验收

- 前端设置测试覆盖 1–32 的配置范围；
- Provider 未就绪时有效批大小不超过 8；
- Provider 就绪且开关打开时有效批大小不超过 32；
- 设置页 GPU 开关在 Provider 未就绪时不可操作；
- 图库分析和单图重新分析都使用有效批大小；
- 前端、Rust、构建和手动启动门禁全部通过。
