# 启动、模型生命周期与分析后端回退

## 目标与假设

- 保留根目录 `启动 PhotoOrganizer.cmd` 作为 Windows 手动验收入口；只使用项目资源和应用自有数据目录，不接触个人照片目录。
- 已打包的 Places365、SigLIP 2、PicoDet/YuNet 和 ONNX Runtime 是现有模型来源，不新增训练集、下载或生产依赖。
- 用户可在设置中选择 GPU 优先或 CPU；模型加载应在应用启动后后台进行，分析操作无需显式“装载模型”。GPU 不可用时以 CPU 完成工作并准确报告实际后端。
- 当前 7 个 Rust 文件已有未提交的分类修改；先保留，再按差异审查，避免覆盖或混入无关改动。

## 风险与验收

- GPU 初始化成功不保证运行时推理成功；验收须覆盖运行时错误后的单次 CPU 回退、后续批次继续、状态与数据库中的实际后端一致。
- 模型资源缺失时，应用必须仍能打开图库，不自动触发下载；错误应可诊断，分析不可误报成功。
- 任务恢复与手动分析不得在模型尚未就绪时竞争或丢失任务。
- 仅使用 `test-data/` 或临时应用数据进行文件测试；不修改原图。
