# 0034 有界滑动窗口导入

## 背景

批量导入几千张图片时，扫描器需要先快速完成目录发现，再逐步生成缩略图和基础特征。真正需要限制的是图片字节、解码图像和处理结果，不能让发现阶段把这些重资源提前积压；同时界面需要先拿到稳定的图片总数，才能准确展示后续完成进度。

## 方案

- 使用固定容量的同步队列连接目录发现和主扫描线程；队列只传递路径，发现阶段保存轻量路径列表，不保存图片字节、解码图像或模型输入。
- 发现线程快速完成递归遍历后，界面先得到完整的“发现”数量；随后处理阶段按固定批次逐步消费路径，处理资源仍由 1–2 个 worker 限制。
- 取消时停止发现线程并释放路径列表；处理中的结果仍按安全边界落库，未访问文件不会被错误标记为缺失。
- 保留每个文件的独立失败记录、缩略图缓存复用、缺失文件收敛和现有进度节流。

## 验收

- 100、1000 张普通图片夹具不会因图像字节或解码图像积压而增加内存峰值，且界面会先显示完整发现数量。
- 导入取消后，发现线程能退出，数据库不会把未访问文件错误标记为缺失。
- 现有重复扫描、缓存重算、损坏文件隔离和子图库 ownership 行为保持不变。

## 验证

- Rust 单元测试覆盖有界发现队列、取消和大批量夹具。
- 使用隔离的临时生成图片做 120+ 张导入基准，不访问用户个人照片目录。
- release 隔离基准使用 1,000 张 `320×240` JPEG：加入批内 worker 后，冷导入 `16.3s`，缓存重算 `14.9s`，热重扫 `3.7s`，三次均 1,000/1,000 完成且失败为 0。
