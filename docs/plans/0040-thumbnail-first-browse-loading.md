# 0040 缩略图优先的连续浏览加载

## 背景

当前图库工作区为了支持“不翻页”的视觉体验，会在进入图库时用并行请求拉取全部资产元数据；随后每个已挂载卡片又立即请求缩略图。对于 3000 张图库，这会同时放大 SQLite 查询、React 节点数量、IPC 调用和缩略图读取，导致重启后首屏迟迟不能稳定显示。

## 决策

- 首次只查询一个工作区批次（当前 `AssetQueryV1.pageSize`，默认 120 张），先让首屏结果和可见缩略图出现。
- 取消中央工作区的“全量预取 + 隐式分页”实现；滚动接近结果底部时追加下一批，视觉上仍是连续的一页，不显示页码控件。
- 追加请求使用当前筛选、排序和图库范围，并用查询 generation 丢弃筛选切换期间返回的旧请求。
- 缩略图只为视口及其附近的卡片排队，前端请求队列最多并发 6 个；同一资产的并发请求合并，继续复用应用会话内缓存。
- 继续使用数据库登记的应用私有缩略图，绝不让浏览流程回退到原图解码。

## 验收

- 3000 张图库进入后先显示首批结果，不等待全部资产元数据返回。
- 初始首屏之外的资产不会在挂载时全部发起 `fetchThumbnail`；缩略图请求数量受可视区域和队列并发上限控制。
- 接近滚动底部时自动追加结果，不出现“上一页/下一页”分页操作。
- 切换图库、筛选、排序或刷新时，旧批次不会污染新结果。
- 现有单图预览、详情缩略图、分组和手动标记行为不回归。
