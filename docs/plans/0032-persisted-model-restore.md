# 0032 模型装载状态持久化与启动恢复

## 目标

用户成功装载一次本地模型后，后续启动不再要求再次点击“装载模型”。模型仍然在每次进程启动时重新创建 ONNX Runtime 会话，但由后台自动完成，界面保持可用并在恢复完成后更新状态。

## 现状问题

- `prepare_semantic_model` 成功后只更新内存中的 classifier，虽然数据库记录了 `semantic_models.is_active=1`，启动流程却无条件创建不可用占位 classifier。
- 启动时在 Tauri 状态安装前恢复任务，会让待处理语义任务先看到不可用模型。
- 前端只在首次请求时读取模型状态，无法收到后台恢复完成的状态变化。

## 设计

1. `semantic_models` 的 active 记录作为“用户曾成功准备过模型”的持久化信号。
2. Tauri 安装 `AppState` 后，在独立线程加载当前随包的 SigLIP 2 + Places365，并同时恢复主体模型；模型加载期间 WebView 不被阻塞。
3. 自动恢复当前随包模型；历史 TinyCLIP/MobileCLIP active 记录按当前 MVP 迁移到 SigLIP 2，不再要求用户重新点击装载。
4. 恢复成功后重新写入 active 模型记录，替换历史版本记录，避免下次启动继续走旧版本。
5. 恢复完成后发送 `semantic-status` 和 `subject-status` 事件，前端即时把按钮从“装载模型”切换到“分析”。
6. 只有模型真正恢复成功后才继续重启时的 queued/interrupted 语义任务；加载失败时保留任务状态和错误日志，用户仍可手动重试。

## 验收

- 首次运行且没有 active 模型记录时，保持轻量启动，不后台加载模型。
- 成功点击一次“装载模型”后退出并再次启动，模型状态最终自动变为“就绪”，无需再次点击。
- 启动期间窗口可以创建，模型加载不会造成黑屏或阻塞 WebView。
- 旧 active 模型记录不会阻止当前 SigLIP 2 恢复。
- 自动恢复后的语义分析、主体分析和智能工作台继续使用同一份当前模型状态。

## 验证

- Rust 单元测试覆盖 active 模型键的持久化读取。
- 前端类型检查、Lint、Vitest 和 Rust 编译/测试验证启动状态事件的类型与调用链。
