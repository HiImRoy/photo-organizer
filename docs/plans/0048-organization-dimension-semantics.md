# 0048 整理目录维度语义澄清

## 背景

整理预览中的每一行同时包含两个不同的决策：左侧决定“按什么信息建立这一层目录”，右侧决定“该信息缺失时如何处理”。当前控件只显示“年”和“修改时间回退”等短标签，且所有维度都可以选择修改时间回退，容易让用户误以为修改时间可以替代题材、影调或颜色。

## 范围

- 保留现有 `OrganizationLevelKind` 和 `OrganizationMissingFallback` 的 IPC 数据结构，不改变整理预览的只读和安全边界。
- 为目录维度使用面向摄影整理的中文名称，并在每一行展示一个简短的规则解释和示例。
- 将缺失处理明确标为“缺失时”，日期维度才提供“用文件修改时间”；非日期维度自动回退到“放入未知”，并不再展示该无效选项。
- 为全局缺失元数据策略补充“命名/元数据字段”语义说明，避免与目录层级回退混淆。
- 在 Rust 校验层拒绝非日期维度使用 `modification_time`，防止绕过前端后生成含义不正确的方案。

## 不在本次范围

- 不改变目录路径渲染算法、文件命名模板、冲突处理和实际文件操作边界。
- 不新增模型、数据库字段或第三方依赖。

## 验收标准

1. 用户能从页面文字看懂第 N 层如何嵌套，以及左侧选择项和右侧缺失处理的区别。
2. 选择“主要题材、影调、主色或饱和度”等非日期维度后，右侧不出现“用文件修改时间”，已有无效值会自动变为“放入未知”。
3. 日期维度仍可使用文件修改时间回退；其他三种缺失处理保持可用。
4. 后端规则校验对非日期维度 + `modification_time` 返回错误，现有安全、只读和目标路径测试继续通过。
5. 前端测试覆盖选项变化和自动归一化，文档说明同步更新。
