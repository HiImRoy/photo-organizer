## 1. 审查结论

PhotoOrganizer 已经形成可用的专业摄影工作台骨架：左侧图库与筛选、中央多图/单图浏览、右侧信息检查器、底部 AI 搜索输入面、整理预览和设置页的基本方向是正确的。当前最主要的问题不是缺少视觉装饰，而是以下四类不一致同时存在：

1. **窄桌面布局失效。** 在项目规定的 960×720 兜底尺寸下，默认 6 张/行会把中央卡片压成不可读的竖条，结果工具栏也发生遮挡和丢失。
2. **浏览根与筛选状态仍然混用。** 本地来源、默认收藏和普通收藏夹已经进入统一图库树，但前端仍把收藏夹存放在 `favoriteOnly / collectionId` 筛选字段中，并计入“已应用筛选”，与 0053 的产品模型不一致。
3. **同一查询维度重复出现。** 左侧已有连续亮度、饱和度范围，又保留“影调”和“饱和度级别”离散筛选；用户无法预测组合后的含义。
4. **多代视觉实现叠加。** `src/styles.css` 已有 16,318 行、507 处 `!important`、443 处阴影声明、263 处 8–10px 字号以及 55 处零圆角声明。新拟物、方正扁平、恢复圆角、Codex 式静默控件等多代规则依靠后置覆盖共存，已经成为视觉回归的主要来源。

因此下一轮不应继续逐截图修补。应先冻结交互语义和共享视觉基础，再处理响应式、筛选、整理预览和文案密度。

## 2. 产品与视觉基线

### 2.1 产品对象

- 主要用户：管理数百到数千张本地照片的个人摄影师。
- 高频任务：浏览和初筛、聚焦当前照片、显式批量选择、评分/色标、加入虚拟收藏夹、搜索和相似审阅、生成只读整理预览。
- 核心心理模型：

```text
本地来源（真实磁盘）
  → 浏览与筛选（不改磁盘）
  → 当前图片 / 显式选择
  → 收藏夹（虚拟关系，可多归属）
  → 整理预览（目标结构快照）
  → 后续安全导出
```

### 2.2 视觉方向

保留“Lightroom 式信息密度 + Codex 式安静桌面工作区”：

- 图片是视觉主体，工具保持克制。
- 使用连续侧栏、分隔线、少量单层圆角容器，不使用 SaaS 卡片墙。
- 主要状态依靠轮廓、表面色和文字层级，不依靠大阴影、发光或大幅上浮。
- 同组按钮必须共享高度、圆角、边框、基线和间距。
- 说明文字只在错误预防、不可逆动作或陌生概念处出现一次。
- 不追求“所有元素都能配置”，设置页只展示真实保存且真实生效的偏好。

### 2.3 本轮应保留的实现

以下部分方向正确，不应在后续优化中推倒重做：

- 图库与筛选为左侧两个独立模块，并可调整高度。
- 左右信息栏可调整宽度。
- 右侧信息栏的“文件 → 直方图 → 拍摄信息 → 人工标记”主顺序。
- 设置页“显示 / 处理 / 快捷键”的栏目结构。
- AI 搜索从中央工具栏打开，并在画布下缘使用 Codex 式输入面。
- 图片卡片人工星级和色标在悬停/键盘焦点时出现。
- 多图预览按 2、4、6、8、10、12 张/行离散调整。
- 小列数使用更清晰的应用缩略图，大列数使用更轻量缩略图；不允许为提高清晰度回退到原图解码。

## 4. P0 问题

### P0-01 960×720 下中央图库不可用

**现象**

- 左侧约 270px、右侧约 320px 保持默认宽度，中央只剩约 300px。
- 默认 6 张/行仍被强制执行，卡片缩成极窄竖条，文件名、指标、标签和标记控件无法阅读。
- 结果工具栏的摘要、AI 搜索、分组、分析状态、人工标记和缩放控件不能形成稳定分行，部分内容被遮挡或离开可见区域。

**代码证据**

- 结果工具栏：`src/App.tsx:2063-2137`。
- 当前网格密度直接使用用户值，没有根据中央容器宽度设置可读下限。
- 多代网格和媒体查询规则并存于 `src/styles.css`，后置规则仍允许卡片低于可读宽度。

**优化规则**

1. 用户保存的是“期望列数”，渲染时使用“可用列数”：

   ```text
   effectiveColumns = min(preferredColumns, columnsAllowedByCenterWidth)
   ```

   窗口恢复后回到用户期望值，不篡改设置。

2. 中央卡片可读宽度建议不低于 132–144px；960×720 默认应回落为 2 张/行。
3. 低于 1080px 时，左右栏先收敛到已定义最小宽度，仍保持可见和可拖动。
4. 结果工具栏使用容器宽度响应，不以整页宽度判断：
   - 第一行：结果摘要、AI 搜索、分组；
   - 第二行：人工星级/色标、网格密度；
   - 有待分析/失败项时，分析状态作为独立紧凑组出现；没有时不占位。
5. 每个控制组必须整体换行，禁止组内按钮互相覆盖。

**验收**

- 960×720 下至少显示 2 列完整卡片；文件名、亮度、饱和度和最多两个标签可读。
- 工具栏所有可见控件可点击，无重叠、裁剪或横向页面滚动。
- 从 1440 缩到 960 再恢复时，用户期望的 6 列设置不被改写。

### P0-02 图库浏览根仍被当作筛选条件

**现象**

统一图库树已经同时显示本地来源和收藏夹，但应用状态仍以 `libraryId + favoriteOnly + collectionId` 表达范围。进入默认收藏或普通收藏夹会被计入“已应用筛选”，条件弹层仍可能显示“来源 / 集合 #ID”。这会让用户误以为收藏夹只是当前来源上的一个筛选，并掩盖跨来源收藏夹的真实语义。

**代码证据**

- `src/App.tsx:240` 使用 `libraryId / favoriteOnly / collectionId` 判断浏览范围。
- `src/App.tsx:626-642` 从筛选字段反推当前收藏夹。
- `src/App.tsx:3155-3169` 把收藏和集合生成为筛选条件。
- `src/App.tsx:3342-3350` 把 `favoriteOnly / collectionId` 计入活动筛选数量。
- `src/types.ts:241-275` 仍在 `AssetFilter` 中保存这些旧字段。

**优化规则**

1. 按 0053 已冻结模型，把当前浏览位置独立为 `BrowseRoot`：本地来源、收藏夹或全部图片。
2. `AssetFilter` 只表达内容条件；收藏夹切换不得增加“已应用筛选”数量。
3. 顶部摘要显示：
   - 浏览根名称，例如“默认收藏”；
   - 其上的内容筛选数量，例如“已应用 2 项筛选”。
4. 条件弹层不再生成“来源”“集合 #ID”；收藏夹名称由图库树和摘要承担。
5. 中央内容不得依赖 `selectedLibrary` 才渲染；跨来源收藏夹应按当前 `BrowseRoot` 工作。整理预览仍按 0053 规则阻止跨来源范围。

**验收**

- 从本地来源切换到收藏夹时，活动筛选数保持不变。
- 同一收藏夹可包含多个来源的图片，浏览、评分、色标和搜索不需要伪造当前来源。
- “移动到收藏夹”只改变收藏关系，界面不出现会被理解为磁盘移动的范围提示。

### P0-03 影调与饱和度存在两套筛选语义

**现象**

筛选栏顶部已有连续的亮度和饱和度范围，后面又提供“低调/均衡/高调”和“低饱和/中饱和/高饱和”。两个控件作用于同一底层特征，却没有说明交集、并集和阈值，组合结果不可预测。

**代码证据**

- 连续范围：`src/components/Sidebar.tsx:453-514`。
- 影调离散筛选：`src/components/Sidebar.tsx:516-531`。
- 饱和度离散筛选：`src/components/Sidebar.tsx:553-570`。
- 两套状态同时存在于 `src/types.ts:246-248`。

**优化规则**

1. 左侧查询只保留连续亮度、饱和度范围。
2. “低调 / 均衡 / 高调”和“低饱和 / 中饱和 / 高饱和”保留为：
   - 分组维度；或
   - 范围控件上的快捷预设。
3. 如果作为预设，点击后只修改同一个连续范围，不再生成第二个查询条件。
4. 读取旧持久化筛选时，将旧离散值转换为对应范围；转换完成后清除旧字段，避免隐形叠加。

**验收**

- 用户只需要观察一组范围就能解释查询结果。
- 选择预设后范围滑块同步移动，条件摘要只出现一次。
- 分组下拉框仍可按影调、饱和度级别分组，且不重新分析图片。

### P0-04 样式文件的历史覆盖已经成为回归源

**现象**

样式中同时保留新拟物 token、方正扁平覆盖、恢复圆角覆盖、侧栏专项覆盖和设置页最终覆盖。同一选择状态、按钮和图片卡片在文件内被定义多次。后续规则依靠更高选择器权重和 `!important` 修正前面的规则，因此局部修改很容易让旧规则重新生效。

**量化证据**

- `src/styles.css`：16,318 行。
- `!important`：507 处。
- `box-shadow`：443 处。
- `font-size: 8/9/10px`：263 处。
- `border-radius: 0`：55 处。
- 新拟物设计层从 `src/styles.css:5754` 开始；随后在 `9757`、`10372`、`12913`、`14192` 和 `16020` 附近继续追加覆盖层。
- `.asset-check`、`.tool-button.is-active`、`.asset-card.is-selected` 等核心状态在多个时代重复定义。

**优化规则**

1. 不一次性重写界面；先建立无视觉变化的共享基础：
   - `tokens.css`：颜色、间距、圆角、控件高度、字体层级、阴影、动效；
   - `base.css`：重置、焦点、滚动条和主题；
   - `layout.css`：顶栏、三栏、竖栏和可拖动分隔；
   - `controls.css`：按钮、图标按钮、分段控件、下拉框、对话框；
   - 各工作区独立样式文件。
2. 建立 `Control / IconButton / ToolbarGroup / Surface / Dialog / SegmentedControl` 的共享几何契约，不引入 UI 框架。
3. 每迁移一个组件，就删除它在旧样式文件中的全部历史定义，禁止继续在文件尾追加“最终覆盖”。
4. `!important` 只允许保留在减少动态效果等明确例外；最终目标不超过 10 处。
5. 删除仍存活的 `--neu-*` 设计 token；阴影只保留浮层、焦点和必要的图片层级。

**验收**

- 同一组件状态只有一个权威样式定义。
- 深色、白天、960/1366/1440/1920 下共享控件几何一致。
- 修改一个 token 能同步影响同类控件，不需要新增 `!important`。
- 视觉回归检查覆盖设置页底部按钮、顶部工具栏、筛选按钮、卡片标记和对话框操作组。

## 5. P1 问题

### P1-01 当前图片、显式选择和色标三个状态竞争

**现象**

- 产品上“当前图片”是右侧信息栏跟随的聚焦对象，“显式选择”是批量操作范围，两者应当独立。
- 当前规范中“当前图片同时使用蓝色边框、勾选”与“单击只聚焦、圆形选择控件单独负责勾选”存在冲突。
- 卡片色标会改变卡片表面/边缘，当前图片轮廓又可能使用偏暖颜色，导致用户难以区分当前、选中和色标。

**优化规则**

- 当前图片：单一灰蓝连续外轮廓，使用 `aria-current` 或等价语义，不显示选择勾。
- 显式选择：右上/左上圆形选择按钮带勾，并在卡片上增加不与色标冲突的选择状态；批量操作条只由该集合触发。
- 色标：低饱和背景或内侧色条，永远不覆盖当前图片的灰蓝外轮廓。
- 更新 `docs/ui-guidelines.md`，删除“当前图片必须带勾”的冲突表述。

**验收**

- 只看一张卡片即可判断它是否为当前图片、是否在批量选择中、是否有人工色标。
- 单击卡片不改变批量选择集合；点击圆形选择控件不丢失当前图片。
- 右侧信息栏始终跟随当前图片，而不是任意一个已选图片。

### P1-02 卡片单击被人为延迟 180ms

**现象**

`src/components/AssetCard.tsx:46-120` 为区分单击和双击，使用计时器将单击聚焦延迟 180ms。图片切换和右侧信息更新因此显得迟钝，容易被理解为“点击未响应”。

**优化规则**

- 单击立即更新当前图片和右侧信息。
- 双击在已聚焦图片上进入单图预览；先发生一次立即聚焦没有副作用，无需撤销单击。
- 拖动起点、选择圆钮、收藏按钮和人工标记控件继续阻止冒泡，不触发重复聚焦。

**验收**

- 单击后下一帧出现当前轮廓，右侧信息立即跟随。
- 双击仍只进入一次单图预览，不改变显式选择集合。

### P1-03 AI 搜索与视图切换的生命周期不完整

**现象**

AI 搜索输入面本身方向正确，但：

- 按 Escape 不会关闭搜索，当前全局 Escape 只负责设置、单图返回或清除选择。
- 搜索打开时切换到单图预览，搜索输入面仍覆盖画布底部和胶片栏，单图导航被遮挡。
- 搜索组件初始化时仍无条件读取旧收藏和集合数据，增加了与搜索无关的状态负担（`src/components/WorkflowWorkspace.tsx:122-129`）。

**优化规则**

- Escape 优先关闭最上层搜索浮层，再处理单图返回和清除选择。
- 切换到单图预览时关闭 AI 搜索；或明确将搜索结果作为单图胶片来源。MVP 采用前者。
- 浮层关闭后把焦点还给“AI 搜索”按钮。
- 按工具拆分数据加载；搜索只加载语义检索所需数据。
- 旧 `favorites / collections` 工作台视图在 0053 主路径稳定后删除，避免形成第二套收藏管理入口。

**验收**

- Escape、关闭按钮、再次点击 AI 搜索三种方式都能关闭浮层。
- 搜索打开时切换 G/F 或顶部视图按钮，不会遮挡单图胶片栏。
- 打开搜索不触发收藏夹详情和旧集合接口。

### P1-04 中央结果工具栏缺少稳定的操作层级

**现象**

1440px 下工具栏已经分成两行，但摘要、人工标记、缩放、AI 搜索、分组和分析状态在视觉上像散落的独立片段；960px 下进一步重叠。分析状态标题和两个状态点长期占位，会压缩高频浏览控件。

**建议布局**

```text
第一组：结果数量 / 浏览根 / 筛选数量 / 已选数量
第二组：星级阈值 / 色标多选
第三组：网格密度（Ctrl + 滚轮）
第四组：AI 搜索 / 分组 / 仅在有异常时出现的分析状态
```

- 每组作为不可拆分的 `ToolbarGroup`。
- “已选择 N 张”出现时，顶部批量操作条与结果工具栏保持明确上下关系，不把批量动作塞入同一行。
- 分析状态在待分析数和失败数均为 0 时完全移除；出现时显示数字，例如“待分析 24”“失败 2”。
- 极窄时先隐藏辅助文字，不隐藏控件本身。

### P1-05 右侧信息栏重复展示同一结论

**现象**

当前信息栏的基础顺序清晰，但同一数据在多个段落重复：

- “影调与色彩”已经显示影调、饱和度和主色；
- “分类”再次显示影调、饱和度和主色；
- “语义标签”再次显示拍摄题材和相似度；
- 模型、版本、候选模型、后端、主体模型和人像辅助长期占据主滚动区。

**代码证据**

- 技术信息：`src/components/DetailPanel.tsx:205-238`。
- 分类摘要：`src/components/DetailPanel.tsx:397-410`。

**优化规则**

- 保留现有前半部分，不重构用户已经认可的文件、直方图和拍摄信息。
- “影调与色彩”只展示连续视觉特征。
- “分类”只展示拍摄题材和主体标签，并提供手动修改。
- “语义标签”展示候选与相似度；“不代表概率”的解释改为标题旁信息提示，不长期占一整行。
- 模型、版本和后端收进默认折叠的“技术信息”。
- 分类标题不展示内部 `revision = 0` 一类实现细节。
- “重新分析此图片”保留为该段最右/底部的强调操作，但不增加额外说明。

**验收**

- 右侧滚动长度明显缩短；同一影调、主色、饱和度只出现一次。
- 普通摄影用户不展开“技术信息”也能完成全部人工判断和标记。

### P1-06 整理预览重复解释“只读”，且左侧规则过载

**现象**

同一屏幕同时出现：顶部“只读整理预览”长句、当前查询胶囊、左栏“只读”、中央“只读规划工作区”、右栏“安全边界”。“目录维度顺序”又有解释框、每行说明和缺失元数据总说明，信息重复。中央与右侧在未生成预览时以大面积空容器占位。

**代码证据**

- 顶部和左栏：`src/components/OrganizationWorkspace.tsx:259-279`。
- 目录维度解释：`src/components/OrganizationWorkspace.tsx:321-364`。
- 空状态：`src/components/OrganizationWorkspace.tsx:600-618`。

**优化规则**

1. 安全说明只保留顶部一行：`只读预览 · 不会修改源文件`；移除其他重复只读徽标和说明。
2. 左侧按任务分四段：范围、目标文件夹、目录层级、文件命名。
3. 目录层级增加固定列标题“目录内容 / 缺失时”，让控件本身解释结构；删除“这样理解”说明框。
4. 每行只显示一个短示例；详细说明放入选择项 `title` 或帮助入口。
5. 选择目标目录后立即显示校验状态：空文件夹、非空、位于源目录内、不可写。当前阶段只读检查，不创建目录。
6. 未生成预览时中央只显示紧凑的“尚未生成”；右侧显示“选择映射后查看路径”，不再套大虚线卡片。
7. 0054 实现导出前，目标目录必须为空的规则应在校验状态中明确，而不是等到执行阶段才报错。

### P1-07 无图库/错误状态仍展示可操作筛选器

**现象**

错误夹具中没有图库，左侧仍显示完整色相环、严格程度和范围筛选；这些控件无法产生结果。中央首次导入入口仍是一个孤立的横向说明卡片，错误条只有“关闭”，没有恢复动作。

**优化规则**

- 无图库时保留“图库”和“筛选”轮廓，但筛选内容替换为一行安静空状态：`导入本地来源后可筛选`。
- 首次导入中心只保留图标、标题、一个主按钮和格式提示；“本地处理 / 不修改原图”合并成一行，不做右侧说明列。
- 可恢复错误提供“重试”；需要用户处理时再提供“查看日志”。仅“关闭”不能算恢复路径。
- 右侧信息栏保持“未选择图片”，不显示空技术分区。

### P1-08 扫描和分析任务反馈像两个不同系统

**现象**

扫描进度面板和语义分析任务条同时出现时，标题、进度条、按钮几何、文本层级和占用高度不同。任务信息字号过小，当前文件路径难以读取。

**优化规则**

- 统一为同一 `TaskRow` 结构：任务名、阶段/数量、进度、暂停/继续、取消。
- 扫描可显示发现/完成/失败/跳过；分析显示完成/总数/失败和本地后端。
- 当前文件名使用省略和悬停完整路径；非关键元数据最低 10–11px。
- 终态自动收敛为紧凑结果行，由用户关闭；进行中任务不遮挡结果工具栏。

## 6. P2 问题

### P2-01 全局字号过小

当前存在 263 处 8–10px 字号。1440px 下文件指标、导航计数、模型信息和任务状态已经接近不可读，白天主题中更明显。

建议字体层级：

- 页面/对话框标题：16–18px；
- 面板标题：13–14px；
- 正文和主要控件：12px；
- 文件指标和辅助标签：11px；
- 10px 只用于非关键微型状态；禁止 8–9px 用户信息。

同时提高行高而不是增加卡片外边距，保持摄影工作台的信息密度。

### P2-02 对话框缺少统一焦点生命周期

- 设置页可以用 Escape 关闭，但收藏夹对话框没有统一 Escape、焦点约束和关闭后焦点返回规则。
- AI 搜索自动聚焦输入框，但关闭后没有恢复触发按钮焦点。

所有对话框/浮层应统一：打开时聚焦首个合理控件、Tab 不离开对话层、Escape 按层级关闭、关闭后回到触发按钮。破坏性确认弹窗不因点击背景而直接提交或关闭。

### P2-03 状态文案和内部术语需要收敛

- 用户可见文案统一使用“本地来源”“收藏夹”“当前图片”“已选图片”“整理预览”。
- 删除旧工作台中的“集合”“虚拟集合”“来源筛选”等过渡术语。
- “移动图片”建议改为“移动到收藏夹”；它只在普通叶级收藏夹的直接成员范围出现，避免被理解为移动磁盘文件。
- “相似度”保留，不使用“置信度”“准确率”或“概率”混称。

## 7. 建议实施顺序

本文件确认后，建议拆成五张独立执行计划；不要在一个提交中同时改全部界面。

### 阶段 A：交互契约与样式基础

- 修订 `ui-guidelines` 中当前图片/显式选择冲突。
- 建立共享 token、控件几何和工具栏组，不改变功能。
- 为现有主要界面建立确定性视觉检查清单。

退出条件：共享控件可以替换旧按钮而不改变布局，后续不再新增文件尾覆盖。

### 阶段 B：核心浏览可用性

- 修复 960×720 自适应列数和结果工具栏。
- 分离 `BrowseRoot` 与 `AssetFilter` 的可见语义。
- 删除重复影调/饱和度查询。
- 去除卡片 180ms 单击延迟。
- 统一当前图片、显式选择和色标状态。

退出条件：主图库在四个验收尺寸和两个主题下完成浏览、筛选、标记与收藏闭环。

### 阶段 C：浮层、空状态和任务

- 完善 AI 搜索关闭与视图切换。
- 简化首次导入/错误状态。
- 统一扫描和分析任务条。
- 完成对话框焦点生命周期。

退出条件：所有临时层都可预测地打开、关闭、恢复焦点，不遮挡另一个核心工作区。

### 阶段 D：信息栏与整理预览

- 去除右侧信息重复，折叠技术信息。
- 简化整理预览文案和空状态。
- 增加目标目录只读校验状态；不提前实现 0054 的真实导出。

退出条件：摄影用户无需阅读长说明即可完成整理规则配置和路径检查。

### 阶段 E：历史样式清理与完整回归

- 按组件删除旧样式层、`--neu-*` 和无效 `!important`。
- 校正全局字号、对比度、焦点和减少动态效果。
- 完成视觉、键盘、构建和现有业务测试。

退出条件：核心组件只有一个样式来源，后续修改不再依靠覆盖旧设计。

## 8. 全局验收矩阵

### 8.1 尺寸与主题

- 1920×1080、1440×900、1366×768、960×720；
- 深色、白天；
- 网格 2/6/12 列和单图预览；
- 左右栏最小、默认和最大宽度；
- 图库/筛选 30/70、50/50、70/30 高度。

### 8.2 状态

- 无图库、导入中、分析中、分析暂停、完成、错误；
- 本地来源、默认收藏、普通收藏夹、跨来源收藏夹；
- 无筛选、组合筛选、无结果；
- 当前图片、单选、多选、星级、色标、收藏；
- AI 搜索关闭/打开/有结果；
- 整理预览未生成/已生成/路径冲突；
- 设置三栏目和恢复默认。

### 8.3 操作

- 鼠标单击、双击、滚轮、Ctrl+滚轮、拖动面板；
- G/F、方向键、Enter、Escape、星级和色标快捷键；
- Tab/Shift+Tab、焦点可见、对话框焦点返回；
- 减少动态效果；
- 桌面区域右键不出现浏览器菜单，文本输入仍可使用编辑菜单。

### 8.4 不变量

- 页面不横向溢出；卡片不低于可读宽度；同组控件不拆散。
- 导入、分析、直方图、颜色和模型处理继续只使用应用缩略图或有界缩略图衍生物。
- UI 优化不读取、改写、移动、重命名或删除原图。
- 收藏夹操作只改变虚拟关系。
- 整理预览不创建目录、不复制文件；真实导出留给 0054。

## 9. 明确不在本轮范围

- 更换分类模型、调整标签质量或重新训练模型；
- 修改 0053 已冻结的数据库边界；
- 实现 0054 的导出执行器、覆盖策略和回滚；
- 新增云服务、账号、远程后端或大型 UI 依赖；
- 用原图替代缩略图解决清晰度问题。

## 10. 最终建议

先执行阶段 A 和 B，再继续扩展 MVP 功能。当前设置页、信息栏前半部分和 AI 搜索输入面已经具备可保留的设计基础；真正影响 MVP 完成速度的是窄窗口不可用、图库根/筛选语义混淆、重复筛选和历史 CSS 覆盖。解决这些系统问题后，再做局部美化才不会继续出现“修复一个截图、另一个页面回归”的循环。
