# 0036 缩略图-only 导入与解码

## 目标

把“所有导入/分析/decode 基于缩略图”的约束从文档落实到实现，消除首次导入把完整源图像素解码到内存的路径。

## 执行项

- [x] 将硬规则写入 `AGENTS.md`、架构 ADR 和用户可见文档。
- [x] 用 Windows WIC 从源文件或已读压缩字节直接提取不超过 `640×640` 的像素。
- [x] 删除导入分析路径对完整源图 `DynamicImage` 的 fallback；不支持的格式明确失败。
- [x] 让 screen 预览也使用有界解码，保留显式 original 查看例外。
- [x] 添加高分辨率 fixture，断言冷导入 `source_decode_us == 0`、输出尺寸受限且源字节不变。
- [x] 记录冷导入、缓存重算、热扫描的独立耗时，并复跑全套检查。
- [x] 让 Places365、SigLIP 2、主体模型和缓存重算共用 `640×640` 有界分析缩略图解码器，并拒绝超大缓存条目。
- [x] 在语义任务 worker 校验应用私有 thumbnail 根目录和 `grid-640-v1` 文件名，覆盖恢复任务与失败重试路径。

## 测试约束

仅使用测试临时目录和生成图片；不得扫描用户图库或把个人图片作为基准。性能报告必须至少区分发现、指纹、缩略图提取、缩略图 decode、特征分析、数据库写入。

## 2026-08-17 实测

隔离生成的 16 张 `4000×3000` JPEG（Windows release，WIC bounded decode）：冷导入 `706.0ms`，其中 `sourceDecodeUs=0`、缩略图提取 `438.3ms`、特征分析 `418.6ms`、数据库写入 `14.1ms`，成功 `16/16`；缓存重算 `406.1ms`，源 decode 仍为 `0`；热扫描 `94.7ms`，跳过 `16/16`。输出缩略图为 `640×480`，源文件字节前后保持一致。该基准只测隔离 fixture，不代表用户个人图库的网络/云盘 I/O 延迟。
