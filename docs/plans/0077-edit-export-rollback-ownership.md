# 0077 编辑导出回滚归属安全修复

状态：实现完成；定向与主代理全量集成验证通过

## 目标与范围

建立编辑导出计划到文件操作记录的一对一可验证归属，确保回滚某个计划只检查、删除并更新该计划生成的副本。覆盖同一路径先后导出、较早副本被外部删除、后续副本与较早内容相同的情形。仅修改 `src-tauri/src/workflow.rs` 和本计划；不改数据库 schema、IPC 或前端。

## 调查结论与假设

- `execute_edit_export` 当前为每次执行独立生成随机 `file_operation_jobs.id`，与 `edit_export_plans.id` 无关联。
- `rollback_target` 依据计划目标路径查找最新已完成操作，因此旧计划可能取得后来导出的目标哈希。
- 回滚状态更新也按路径与哈希批量匹配操作，并通过目标路径查询“最新”作业；同路径的多条操作会被一起更新或更新错作业。
- 现有 schema 允许 `file_operation_jobs.id` 使用计划 ID；`file_operations` 通过 `job_id` 归属作业且同一作业/路径最多一条记录。因此新导出以计划 ID 作为作业 ID，无须迁移。
- 旧版计划未保存其随机作业 ID。即使目标路径、源指纹或哈希相符，也无法证明唯一归属；不能按时间或“最新操作”猜测，需明确拒绝该旧计划回滚。
- 仅按计划 ID 绑定操作仍不够：若旧副本被外部删除，随后同路径导出字节完全相同的新副本，两个操作的目标哈希相等。只有同路径最近一次成功的 `edit_copy` 操作归属于当前计划时，才可回滚。
- 文本路径相等不足以代表 Windows 文件身份。新导出计划将父目录规范化；归属、最近成功操作、进行中导出和回滚认领比较都通过项目 `identity_key` 语义识别大小写、分隔符及 `\\?\` 扩展路径别名。
- 当前执行函数内部会重新执行回滚预览校验，但 IPC/API 仍允许直接调用执行函数，不能证明用户显式查看并确认了预览。本任务不改 IPC/API，因此记录此授权风险，不宣称显式预览不可绕过。
- 源图库保护从导出目标验证中抽为私有 helper。回滚预览和执行删除前都 canonicalize 现存目标（跟随 symlink/junction）并验证其身份位于所有源图库之外。
- 保留源指纹校验、目标哈希校验和目标不可覆盖；执行时重新核验计划归属、目标 hash 与源图库边界。

## 实施步骤

1. 先增加回归测试：同一目标路径由两个计划顺序导出；删除首个副本后，旧计划即使与第二次导出字节相同也不得预览或执行回滚；第二个计划可以预览并回滚。另覆盖未关联操作记录的旧版计划返回明确错误。
2. 新导出用 `plan_id` 同时作为 `file_operation_jobs.id` 和 `file_operations.job_id`，保持每个计划与操作记录直接关联。
3. 回滚查找仅接受该计划 ID 下唯一的、目标路径匹配且执行已完成的 `edit_copy` 操作；缺失、重复或不匹配时明确拒绝。不得回退到按路径寻找记录。
4. 同时要求该操作是相同文件身份最近一次成功的 `edit_copy`；有更新的成功操作时，旧计划即使 hash 相同也拒绝预览和执行回滚。任一同身份的其他 `edit_copy` 仍为 `running` 时也拒绝，不依据行 ID 新旧推断其已停止。
5. 回滚执行通过短事务提交 durable `rollback_status='running'` claim。提交后在事务外重新 canonicalize、验证目标仍在图库之外并复核 hash，再删除；最终状态在独立短事务中原子更新到该计划的操作、作业与计划。导出登记用短事务检查回滚 claim，并与 rollback claim 串行化；文件 I/O 期间不持有 SQLite 写事务。
6. 定向运行所有 `workflow::tests`、格式检查及相关 Rust 静态检查；遵守默认 Cargo 锁，不清理 `target`。审阅最终 diff，并在本计划记录结果、未运行检查及限制。

## 验收

- 回滚只能寻址与指定计划 ID 明确关联且为该路径最近一次成功导出的操作；无法安全识别的旧版计划收到显式错误。
- 两个相同目标路径、相同导出字节的计划互不影响；旧计划不能删除新计划的副本，新计划可正常回滚。
- 执行时重新核验计划归属、当前目标 hash 和规范化目标仍位于所有源图库之外；导出仍使用 `create_new`，不覆盖现存文件。
- UI 保留预览与执行两步，但这只是 UI 二步；执行 API 可直接调用，显式预览授权令牌不在本任务范围。
- 测试文件操作只发生在测试自有临时目录，原始 fixture 保持不变。

## 风险与范围限制

- 本修复不会建立 IPC 层的预览确认令牌。`execute_edit_rollback` 会重新执行预览时的所有权与目标哈希检查，但具备 IPC 调用能力的客户端仍可直接请求执行；显式预览授权仍未解决。
- durable claim 在执行删除前已提交。若进程在 claim 后、最终状态事务提交前崩溃（包括文件已删除而状态更新失败），日志会保留 `rollback_status='running'`，同身份导出与其他回滚会安全拒绝；自动恢复/人工恢复 UI 未实现。
- 导出作业 ID 使用计划 ID；作业与操作行在同一短事务登记，避免部分写入。若进程在该事务提交后、导出到达终态前崩溃，作业仍为 `running`，重试会因同 ID 冲突被拒绝；本轮不实现恢复流程。
- 规范化/哈希核验与按路径删除不构成原子操作；外部并发替换仍有竞态，尤其哈希读取期间及核验完成到删除之间。本里程碑如实记录此限制，不宣称文件系统 compare-and-unlink 原子性。
