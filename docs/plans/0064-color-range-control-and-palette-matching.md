# 0064 颜色范围控件与调色板匹配

状态：已实现；颜色代码已通过隔离验证，工作树另有既存分类改动的编译阻断

## 目标与边界

为本地照片筛选提供不易误操作的色相范围控件，并让高严格度筛选真正接近肉眼识别的主色。继续使用应用私有缩略图生成的面积色调色板（`coveragePalette`）和多个强调色（`prominentPalette`），不读取原图像素、不训练新模型、不新增运行时依赖，也不改变原文件。

当前故障：环上所有指针事件落在同一个 SVG，端点附近的 12° 热区与整段转动热区重叠；松开后再点击可能意外重置中心。查询只计算 12 桶色相直方图中命中桶的比例，桶边界把不同颜色并为同一色，即使严格度最高仍可能让视觉主色不一致的照片通过。

## 交互方案

- 以暗房色轮为视觉隐喻，沿用现有低饱和灰蓝表面色和控制几何；只有色相环呈现完整色谱，不增加装饰性渐变。
- 明确区分三个动作区：未选色轮上的点创建范围；范围弧本体拖动整个范围；两个可见端点各自调整边界。指针按下后锁定动作，拖动过程中绝不切换模式。空白区域单击可重新定位，但拖动空白区域不能产生无意的旋转。
- 端点命中区与弧命中区不重叠，控件说明与指针样式准确表达动作；支持键盘调整、聚焦状态和触摸，保留清除及严格度滑块。
- 按项目共享控件半径与亮暗主题规则检查窄侧栏。

## 匹配方案

- 参考 AndroidX Palette：`dominant` 由最大像素 population 定义，Vibrant/Muted 等目标色在饱和度、亮度与 population 之间权衡。现有 `coveragePalette`/`prominentPalette` 已分别承载面积和显著性角色；本项目对足量彩色面积保留已有主色优先规则，严格匹配所说的“主色”须与 UI 展示的首个面积候选一致，而不是重新按最大面积选灰色。复用已有 OKLab 聚类，不改成另一个提取器，也不把强调色当作面积主色。
- 先由连续色相角度判断面积色候选是否落在用户选定范围，再以面积覆盖率及主色排序衡量视觉一致性，避免只靠 30° 直方图桶。
- 多个面积色可共同贡献命中面积；强调色只能提供有限辅助证据，不能单独把主色明显不同的图片推过最高严格度。
- 严格度提高时提高主色一致性和面积要求，并收窄容差；宽松度仍允许有意义的强调色命中。候选数量不能凭重复计数刷高得分。
- 兼容旧的数组调色板和缺失调色板记录，避免查询失败；其回退应明确、保守。筛选总数与分页走同一谓词。

## 验收

- 端点拖动只改变宽度，弧拖动只转动，空白点击不误触端点；包含跨 0°、快速拖动、取消拖动与键盘边界测试。
- 红主色与蓝主色在高严格度下分离；同一视觉主色的近似色可以通过；大面积中性色加少量高彩强调色不能伪装成目标主色；多个面积色与多个强调色可在合理严格度下提供辅助命中。
- 前后端阈值说明一致，已有测试更新；运行格式、lint、类型、前端及 Rust 测试、clippy、构建，并复查未提交的既有改动没有被覆盖。

## 成熟方案参考

- [AndroidX Palette 官方 API](https://developer.android.com/reference/androidx/palette/graphics/Palette)：dominant swatch 取最大 population，另有独立的 vibrant/muted swatch。
- [Android Developers — Palette colors](https://developer.android.com/develop/ui/views/graphics/palette-colors)：目标色评分结合饱和度、亮度与 population。
- [Vibrant 项目](https://github.com/akigami/vibrant)：量化器、生成器和过滤器可分离；本项目借鉴角色分离，不新增 JS 运行时依赖。
