## 目标

交付一个 Windows 优先、离线可用的真实纵向切片：选择测试图库、递归扫描 JPEG/PNG/WebP、持久化 SQLite 索引、生成应用私有缩略图、计算基础亮度/饱和度/主色、在桌面 UI 中增量展示与排序，并提供可取消的后台扫描。完成自动化验证与 Windows 安装包构建尝试。

## 范围与假设

- 采用 Tauri 2、React、TypeScript 和 Rust；本里程碑不引入 Python sidecar。
- SQLite、文件扫描、缩略图、传统图像分析和任务调度在 Rust 进程内完成。
- 不下载或伪造语义模型；仅交付分类器接口、后端抽象、模型元数据、明确的未安装状态和可执行基准入口。
- 扫描只读源文件；缓存与数据库写入应用数据目录或测试临时目录。
- 自动化文件系统测试只使用 `test-data/` 及测试创建的临时目录。
- 本里程碑不实现复制整理 UI；安全复制、dry-run 和回滚属于下一里程碑，但数据模型和边界已预留。

## 重要决策

1. 选择“Rust 单进程纵向切片 + 可插拔 ONNX 适配层”，理由见 ADR-0001/0002。
2. MVP 不把 Python、OpenCV、ExifTool 或模型权重放入安装包；基础 EXIF/图像能力用 Rust 库实现。
3. 语义模型必须经过许可证核验与目标数据基准后才可成为默认组件，理由见 ADR-0003。
4. 前端通过类型化 Tauri commands 和事件读取后端状态；不运行本地 HTTP 服务。

## 新发现的风险

- 正式 Windows 安装包依赖 Rust MSVC target、C++ Build Tools、WebView2 和打包器；当前机器明确缺少 `link.exe`。
- WebP/EXIF 的边界行为依赖选定 Rust crate，需用损坏文件、方向和 Unicode 路径测试验证。
- 没有经过许可证与性能评估的语义模型，因此本里程碑不会输出内容标签。
- 大图库的网格虚拟化和吞吐调优不作为起步阻塞项；当前实现需保留分页接口并记录规模限制。

## 偏离与原因

- 基础图像和 EXIF 能力在 M0 使用 Rust crate，而非 Python/OpenCV/ExifTool sidecar，避免安装体积和跨进程失败面；接口和数据版本为后续替换保留。
- 用户补充要求前端采用新拟物风，因此在功能完成后统一视觉 token、浮起/按压态和无障碍反馈，未改变业务范围。
- 本机正式 MSVC 打包受 `link.exe` 缺失阻塞；只为验证安装链路使用临时 GNU/LLVM 环境生成未签名 NSIS，正式发布仍锁定 MSVC CI。
