# Plan 0017 — Import regression audit and task surface hierarchy

## 目的

在不改变 Checkpoint A 的图库、来源归属、递归扫描、父子图库和缺失检测语义的前提下，确认当前导入变慢的实际阶段，并修正后台任务与图片区的视觉层级。

## 审计结论（2026-08-09）

### 导入业务逻辑没有在本轮被改写

当前工作区本轮未修改 `src-tauri/src/scanner.rs`。Checkpoint A 的关键约束仍由现有扫描器维护：

- 选择一个来源目录建立一个图库。
- 显式导入的子目录作为独立来源图库，并按来源层级初始化关系。
- 父图库扫描会 prune 已导入的 descendant SourceRoot。
- 资产归属继续使用 Most Specific Imported Library Owner。
- 扫描、缩略图和分析不写回原始图片。

此前性能提交只改变了像素处理和进度写入方式，没有改变上述业务归属规则。

### 解码与缓存路径

| 场景               | 当前行为                                                                                                            | 结论                                                     |
| ------------------ | ------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 首次导入或文件变更 | 对原图做一次完整解码，按 EXIF 方向处理，再生成一份 `grid-640-v1` 缩略图；影调/色彩特征从同一份 640 缓冲区采样       | 这是冷导入的主要成本，不能用尚未存在的缩略图替代原图解码 |
| 未变化的再次扫描   | 文件大小、修改时间、分析版本、缩略图状态和缓存文件都有效时，直接 `touch_asset_seen`，跳过指纹、解码、缩放和特征分析 | 缩略图缓存正在使用；热重扫不应重新解码                   |
| 网格显示           | 通过 `get_thumbnail_data_url` 读取已登记的 `grid-640-v1` 缓存                                                       | 不读取原图                                               |
| 单张屏幕预览       | 读取独立的屏幕预览缓存；首次缓存未命中时才从原图生成                                                                | 与导入缩略图缓存分开，避免把高清预览误当成导入缓存       |
| 原图预览           | 仅在明确请求 `original` 层级时读取原图                                                                              | 不属于图库导入流程                                       |

之前记录的真实测量仍然与代码路径一致：完整解码约占图像处理时间的 77.6%，缩放/方向处理约占 20.1%，指纹、SQLite 和缩略图写入均不是主要瓶颈。

### “包含子文件夹”选项的额外成本

选中该选项时，启动扫描前会先遍历一次来源树，找出每个直接包含图片的目录；随后父来源和每个显式子来源分别按 ownership scope 扫描。这个额外目录遍历是为了建立用户要求的独立图库，不是图库层级被错误地改回磁盘目录树。

当前 `discover_import_source_roots` 在 IPC 调用返回前执行，因此目录非常大时可能先出现短暂的“无响应”；任务开始后仍然是串行的原图解码。后续性能优化应分别测量“来源树发现”和“图像解码”，不能通过删除子图库或 ownership prune 来换取速度。

## 本次实施

- 将 `ProgressPanel` 和 `SemanticTaskBar` 移到 `center-column`，与图片区 `center-workspace` 成同级关系。
- 保留各任务面板自身的单层圆角表面，避免出现在图片区卡片内部的双层圆角。
- 增加前端回归断言，确保后台任务不会重新成为 `center-workspace` 的后代。

## 明确不做

- 不删除或改变 `includeSubfolders` 行为。
- 不删除父图库 prune、Most Specific Owner Resolver、指纹和真实路径数据。
- 不把原图误替换成低分辨率缩略图作为唯一分析输入。
- 不在缺少 Release 基准和内存预算的情况下盲目并发解码。
- 不在没有 ADR 的情况下引入新的 JPEG 解码依赖。

## 下一步性能门槛

用同一份仓库测试数据分别验证冷导入、热重扫和“包含子文件夹”导入：热重扫必须保持零图像处理；只有确认冷导入仍由完整解码主导后，才评估带内存上限的两路并发或 decoder-level bounded decode。
