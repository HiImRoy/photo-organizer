# 主体标签与本地模型工作流计划

## 目标

在 Places365“拍摄题材”之外，增加独立的主体标签层，解决“有人/多人/人像、车辆、动物、食品”等内容属性不应由场景模型推断的问题。

## 第一版能力

主体模型只输出辅助标签，不参与主拍摄题材竞争，也不改变物理目录结构：

| 稳定 ID    | 中文显示 | 触发依据                 | 说明                                           |
| ---------- | -------- | ------------------------ | ---------------------------------------------- |
| `person`   | 人物     | COCO `person` 或人脸检测 | 表示画面中检测到人物                           |
| `group`    | 多人     | 检测到至少 2 个可信人物  | 与 `person` 并存，不是互斥类别                 |
| `portrait` | 人像     | YuNet 检测到可信人脸     | 不是身份识别，不保存人脸向量                   |
| `animal`   | 动物     | COCO 动物类              | 不细分成稳定主类别                             |
| `pet`      | 宠物     | COCO `cat` / `dog`       | 作为动物的更具体辅助标签                       |
| `vehicle`  | 车辆     | COCO 交通工具类          | 覆盖汽车、公交、火车、飞机、船等               |
| `food`     | 食品     | COCO 食品与餐饮类        | 只作为主体证据，不能替代 `photo_food` 场景题材 |
| `plant`    | 植物     | COCO `potted plant`      | COCO 没有通用花卉类，第一版不伪造“花卉”识别    |

`person`、`group`、`portrait` 可以同时存在；例如一张多人合影会得到“人物 + 多人 + 人像”。主体标签永远不会写入 `primary_category`。

## 模型选择

- PicoDet-S 320 COCO：轻量目标检测，使用官方后处理 ONNX 输出，适合本地 CPU 与缩略图输入。只读取 80 个 COCO 类，不做开放词汇提示词。
- YuNet 2023mar：轻量人脸检测，仅用于支持“人像”标签。第一版不做身份识别、聚类、年龄/性别推断，也不保存人脸框或 embedding。
- 两个模型均在应用资源目录中固定版本、SHA-256、来源和许可证；模型缺失时主体层显示“未启用”，场景层仍可独立工作。

## 工作流

1. 扫描阶段生成当前 `grid-640-v1` 缩略图。
2. 语义任务只选择当前缩略图和 fingerprint 有效的资产，禁止主体模型打开原图。
3. 每批先运行 Places365，再运行主体模型；两个推理过程均可失败隔离，主体失败不抹掉已经成功的场景结果。
4. 主体模型输出先经过固定阈值、类别归并和人数规则，再写入 `subject_analysis_runs` 与 `subject_labels`。
5. 写入前重验 fingerprint；源文件变化则跳过本次结果，旧结果不会冒充当前图片。
6. 任务暂停、继续、取消、重启恢复沿用现有 `analysis_jobs` / `analysis_job_items`；主体模型版本变化会通过新的 run key 自动触发重分析。
7. 清除主体派生数据只删除本地数据库中的 run 和 label，不触碰原图、缩略图或目录。

## 不做的事情

- 不做人脸身份识别，不建立人物身份聚类。
- 不根据检测框推断摄影风格、性别、年龄、情绪或职业。
- 不把单张图片的主体标签自动变成物理文件夹。
- 不用 K-Means 或当前图库分布动态生成标签；标签 ID 必须跨图库稳定。

## 验收标准

1. 主体 catalog 与场景 catalog 分组显示，界面全部中文。
2. 100% 的主体推理输入来自应用缩略图路径，测试禁止传入原图路径。
3. 空检测结果也要写入成功 run，避免每次分析重复处理同一张图。
4. 模型缺失、单张失败、源 fingerprint 变化、暂停/取消和重启恢复均有明确状态。
5. 主体标签可用于现有辅助标签筛选，并与手动添加/移除规则合并。
6. Rust 单元测试、模型契约 smoke test、前端类型/lint/test/build 全部通过。
