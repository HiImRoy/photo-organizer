# ADR-0007：使用 Places365 叶子证据并映射为稳定中文摄影题材

- 状态：已接受
- 日期：2026-08-10
- 关联计划：`docs/plans/0026-places365-scene-clustering.md`

## 背景

早期语义分析使用 TinyCLIP 对一组手写英文提示词做相似度排序。相似度不是概率，提示词之间也没有经过校准，导致“车辆”“街道”“未知”等结果在不同照片上出现系统性偏置。该方式适合作为开放词汇检索或相似搜索，不适合作为图库的稳定主类别。

用户已经确认采用 Places365，并希望将餐馆、咖啡厅等相近场景聚合成更少、更易理解、贴近个人摄影的题材。Places365 是固定 365 类的场景分类模型，因此把“叶子预测”和“产品展示题材”分开管理。

## 决策

采用两层结构：

1. Places365 模型输出固定的 365 个场景叶子标签，并保留叶子 ID、概率和模型版本作为分析证据。
2. 应用使用版本化的人工维护映射，将每个叶子标签归入 11 个互斥的中文摄影题材。主类别只从这 11 个题材中选一个；聚合置信度不足时返回虚拟“未知”。映射保留 Places365 原始场景桶作为完整性校验，并用显式覆盖把餐饮、旅行、植物从宽泛桶中拆出。

SigLIP 2 负责当前摄影题材候选，Places365 只提供场景证据。人物、车辆、动物、花卉、食品、文档等主体或内容类型需要独立的多标签模型，不由 Places365 强行推断；尤其人物/人像需要单独的人物检测或主体模型。

## 备选方案

- **继续扩大 TinyCLIP 提示词**：无需新模型，但仍然缺少校准，且提示词、语言和类别数量会改变结果，不能解决当前偏置。
- **对当前图片嵌入做 K-Means**：可以得到图库内相似簇，但簇 ID 不稳定，新增图片会改变旧簇语义，不适合作为产品主类别。
- **直接显示全部 365 类**：信息过细，筛选和人工修正成本高，也不符合照片管理的工作流。
- **让 Places365 直接输出人像/人物**：模型训练目标是场景而不是主体，容易把人物照片误归到街道、室内或其他环境题材，因此单独建模。
- **引入通用视觉语言模型**：主体覆盖更广，但模型体积、运行时间和本地部署复杂度明显增加，超出当前里程碑。

## 影响与迁移

- 新版本使用新的模型名、分析版本和 taxonomy 版本。数据库查询只读取当前三者匹配且源指纹一致的自动标签，因此旧自动结果不会混入新分类。
- 现有人工分类覆盖不被删除；手动值仍按稳定 ID 保存，并由前端中文字典显示。旧自动值只作为兼容数据存在，重新分析后由新题材替换。
- 新增迁移用于保存 Places365 叶子证据，原始图片和原始目录不会被修改。
- Places365 模型资源必须在应用资源目录中离线可用，并在资源文档中记录来源、许可证和 SHA-256；模型缺失时显示“模型未就绪”，不能静默把旧题材模型结果冒充 Places365。

## 风险

- Places365 只理解场景，不能可靠判断照片主体。主体标签需要单独的模型和阈值策略。
- 11 个题材是产品 taxonomy，不是 Places365 官方层级；边界需要通过真实图库样本验收，并以新的 taxonomy 版本迁移。
- 聚合概率受叶子数量和场景分布影响，因此实现中同时使用聚合概率、第一/第二名差值和拒识阈值，避免大桶天然压制小桶。
